# Human Test Checklist: new duchies get their counties, and the `duchies` question

**Target version:** 0.6.51
**Ships with commit:** v0.6.51 (TBD at writing)
**Companion automated tests:** `tests/test_transplant.py::test_s4_...` (the move, the county left alone, unheld, a second run, the `l` answer); `tests/test_choices.py` (the `duchies` answers under `all`, `all=mygame`, `all=newgame`, and explicitly); `tests/test_update.py` (the question list in an `--auto` error, `all=newgame` reaching the asker).

## What this is

A newer game splits some old duchies: it moves a few counties into a duchy of its own. Updating a 1.8 save to 1.20, the tool already wrote those new duchy titles, but left their counties in the old duchies. So the new duchies were empty titles, and in 1.21 an empty duchy has no market.

The update now moves each such county into the duchy a new game puts it in. The new duchy is unheld, as in a new game; nobody is given it. A county whose new-game duchy your campaign already had stays where your campaign put it. The `duchies` question lets you keep everything as the game itself would (`l`). This checklist is for a person with a 1.8 save and the game.

## Prerequisites

1. The tool at 0.6.51, a 1.8 save (`old.ck3`), and a 1.20 reference save (`ref.ck3`, a new 1.20 game on day one).
2. **Isolation:** write every output to a scratch folder. The tool never writes in place. Name any save you load in the game `MIGRATE_TEST__...`.
3. Between sections, start again from `old.ck3`; nothing carries over.

## High-Value Verification (~5 minutes)

### HV.1: the counties move, and the report names them

- [ ] **Steps:** `ck3update migrate old.ck3 --rules all,R15,R14,R16 --reference ref.ck3 --report r.json -o <scratch>/out.ck3`
- [ ] **Expected:**
  - R14's report says `new_duchies_given_their_counties: fix: N counties into M duchies` (the founding campaign: 54 into 27).
  - R17's report lists `counties_to_new_duchies` as `c_x -> d_y` lines.
- [ ] **Why this matters:** without it, the new duchies stay empty titles.

### HV.2: the purist answer leaves everything

- [ ] **Steps:** the same command with `--auto duchies=l` (or `--auto all=newgame`), to `<scratch>/out_l.ck3`.
- [ ] **Expected:** R14 says `left as the campaign had them`; R17 lists no counties moved.
- [ ] **Why this matters:** it is the promised "as the game intended" mode.

### HV.3: a misspelled answer stops before anything runs

- [ ] **Steps:** `--auto duchies=x`.
- [ ] **Expected:** an error naming the answers `f (fix), l (leave)`, and nothing written.
- [ ] **Why this matters:** a typo must not silently pick an answer.

### HV.4: in the game, a new duchy has its counties

- [ ] **Steps:** load `<scratch>/out.ck3` (as `MIGRATE_TEST__duchies.ck3`) in 1.20; open a duchy the report named, for example Akaltay in the Altai on the founding campaign.
- [ ] **Expected:** the duchy shows its de jure counties and no holder. The old duchy (Altay) no longer lists them.
- [ ] **Why this matters:** the save checks predict this; the game is the judge.

### HV.5: in 1.21, those duchies have markets

- [ ] **Steps:** load the 1.20 result in 1.21 (its first load converts it), then save. Count markets (the trade map), or compare against the same save made with `--auto duchies=l`.
- [ ] **Expected:** more markets than the `l` save, one per newly filled duchy (the founding campaign: 9 more).
- [ ] **Why this matters:** the markets are the reason for the change.

---

## Section 1: what does not move

### 1.1 a county in a duchy your campaign already had

- [ ] **Steps:** in `r.json`, check that no county moves into a duchy that existed in your 1.8 save.
- [ ] **Expected:** only duchies new since 1.8 appear on the right of `counties_to_new_duchies`.

### 1.2 holders unchanged

- [ ] **Steps:** pick a moved county; compare its holder in `old.ck3` and `out.ck3` (the game's county view, or the save).
- [ ] **Expected:** the same holder. Only the de jure duchy changed.

## Section 2: the question at a terminal

### 2.1 asked once

- [ ] **Steps:** run `ck3update update` interactively on a 1.8 save.
- [ ] **Expected:** the `duchies` question appears once, with a count, and `f` is the default (Enter).

## What the automated tests DON'T cover

- The game's own view of the duchies (HV.4) and the 1.21 markets (HV.5).
- The prompt's wording and layout at a real terminal (2.1).
- Your campaign's own de jure history: a moved county the old duke would rather keep (a design choice; `l` is the way out).

## Reporting issues found

Note the section and step, the command and its output, and keep `r.json`. File an issue referencing this checklist and v0.6.51.

## Cleanup

Delete the scratch outputs and any `MIGRATE_TEST__duchies*.ck3` from your save games folder. Your own saves are untouched.
