# Human Test Checklist: the save editor (`ck3update edit`, set-sex first)

**Target version:** 0.5.10 (the editor was built across 0.5.1 to 0.5.10)
**Ships with commit:** v0.5.10: edit --list, help <edit>, and the Editing a save page
**Companion automated tests:** 79 tests in `tests/test_patch_format2.py` (13), `tests/test_edit_cli.py` (9), `tests/test_edit_ledger.py` (5), `tests/test_edit_revert.py` (7), `tests/test_edit_inplace.py` (8), `tests/test_dangerous.py` (4), `tests/test_edit_ironman.py` (7), `tests/test_characters.py` (8), `tests/test_edit_set_sex.py` (10), `tests/test_edit_list.py` (8). Whole suite: 1325 passed, 7 skipped.

## What this is

A hand-run companion to the editor's automated tests. A person walks through it to check what the tests cannot: how the output reads at a real terminal, the question before writing, how long a real save takes, and above all how an edited character looks in the game. The tests run on synthetic saves of a few kilobytes; this checklist uses a real one.

Codes used here:

| Code | Meaning |
|---|---|
| HV.n | a High-Value Verification step, the five-minute pass |
| MANUAL | a step only a person can do (the game, a terminal prompt, a judgement by eye) |

## Prerequisites

1. `ck3update --version` prints 0.5.10 or later (or run `python -m ck3_save_migrator` from the repository).
2. A real text save (not ironman). **Work on a copy, in a scratch folder. Never run these steps on a save you play.**
3. Know one character in it with a common first name, and one character's id. `ck3update edit <copy> set-sex <first name> male --dry-run` lists candidates with their ids when the name is shared.
4. A scratch config, so your own settings are not touched (Section 3 only).

Set up the scratch folder and the copy (pick your shell):

**cmd.exe**:
```cmd
mkdir %TEMP%\ck3edit
copy "C:\path\to\My_Campaign.ck3" %TEMP%\ck3edit\Camp.ck3
cd /d %TEMP%\ck3edit
```

**PowerShell**:
```powershell
New-Item -ItemType Directory -Force "$env:TEMP\ck3edit" | Out-Null
Copy-Item "C:\path\to\My_Campaign.ck3" "$env:TEMP\ck3edit\Camp.ck3"
Set-Location "$env:TEMP\ck3edit"
```

**POSIX**:
```bash
mkdir -p /tmp/ck3edit && cp "/path/to/My_Campaign.ck3" /tmp/ck3edit/Camp.ck3 && cd /tmp/ck3edit
```

**Reset between sections:** delete every file in the scratch folder except `Camp.ck3` (see Cleanup for the commands). `Camp.ck3` itself must never change; step 1.4 checks that.

## High-Value Verification (~5 minutes, plus the game for HV.3)

### HV.1 The list and the help read well

Validates: a new player can find the edits and learn what one takes.

- [ ] **Steps** (same in every shell):
  ```
  ck3update edit --list
  ck3update help set-sex
  ```
- [ ] **Expected:** a table with `E1 set-sex edits ready`, `E2 ironman-off` and `revert`, columns aligned. The help shows the usage line `ck3update edit <save> set-sex <who> <sex>`, both values with their types, and a paragraph.
- [ ] **Why this matters:** an edit nobody can discover or understand is not usable, however correct.

### HV.2 set-sex finds a character by name and shows the plan

Validates: the resolver on a real save, and the plan a player confirms.

- [ ] **Steps** (same in every shell; use your character):
  ```
  ck3update edit Camp.ck3 set-sex "<First name> <parent's first name>" male --dry-run
  ```
- [ ] **Expected:** a `target :` line naming one character with id, sex, age, birth date, house, father and mother. One `change at ...` line showing `female=yes` removed (or added, for `female`). `dry run: nothing written`. No new file in the folder.
- [ ] **Check:** it took seconds, not minutes (about 15 s on a 240 MB save).
- [ ] **Why this matters:** the wrong character edited silently would be the worst failure this feature has.

### HV.3 The edited character in the game (MANUAL)

Validates: the half no test can: how the character looks and behaves after the edit.

- [ ] **Steps:**
  1. `ck3update edit Camp.ck3 set-sex <id> male --yes` (a child is the most telling case).
  2. Copy `Camp__set-sex.ck3` into the game's save folder under a name that marks it as a test.
  3. Load it in the game and open the character.
- [ ] **Expected:** the game loads the save. The character is shown as male. The face is recognisably the same person. Family and titles are unchanged.
- [ ] **Check by eye:** does the portrait read as a boy (or a girl), or does it look wrong? Note anything odd: clothing, hair, voice, pronouns in event text.
- [ ] **Why this matters:** the edit changes one line; whether the game draws a believable person from it is the feature's real result.

### HV.4 revert gives the original back

Validates: every edit can be undone.

- [ ] **Steps** (same in every shell):
  ```
  ck3update edit Camp__set-sex.ck3 revert --yes
  python -c "import sys,hashlib;from ck3_save_migrator.savefile import read_save;[print(hashlib.sha256(read_save(p).gamestate).hexdigest(),p) for p in sys.argv[1:]]" Camp.ck3 Camp__set-sex__revert.ck3
  ```
- [ ] **Expected:** the two lines carry the same hash (the save's contents, uncompressed). The files themselves may differ in size, since the tool compresses again.
- [ ] **Why this matters:** a player who regrets an edit must get their save back exactly.

### HV.5 `--in-place` keeps a backup

Validates: the original is never lost by default.

- [ ] **Steps** (work on a second copy, `Camp2.ck3`):
  ```
  ck3update edit Camp2.ck3 set-sex <id> male --in-place --yes
  ```
- [ ] **Expected:** `Camp2.ck3` is the edited save, `Camp2.bak.ck3` is the original, and `Camp2.edits.json` is the ledger.
- [ ] **Why this matters:** in-place is the one mode that replaces a file a player cares about.

## Section 1: the front door

### 1.1 The question before writing (MANUAL, a real terminal)

- [ ] **Steps:** `ck3update edit Camp.ck3 set-sex <id> male`, then press Enter at `Write Camp__set-sex.ck3? [y/N]`.
- [ ] **Expected:** `not written`, no new file. Run it again and answer `y`: the file is written.

### 1.2 A shared first name is refused with candidates

- [ ] **Steps:** `ck3update edit Camp.ck3 set-sex <common first name> male`
- [ ] **Expected:** an error saying how many living characters match, then one line each: id, sex, age, birth, house, parents, titles, youngest first. Nothing written.
- [ ] **Check by eye:** is the list readable at 30 rows? Can you tell the candidates apart?

### 1.3 Refusals say what to do

- [ ] `set-sex <id> dragon`: "the sex is male or female".
- [ ] `set-sex <id> <the sex they already have>`: "is already ...", nothing written.
- [ ] `set-sex 999999999 male`: "no living character has the id".
- [ ] `ck3update edit Camp.ck3 no-such-edit`: names the known edits.

### 1.4 The original never changes

- [ ] **Steps:** run this before Section 1 and after it (same in every shell):
  ```
  python -c "import sys,hashlib;print(hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest())" Camp.ck3
  ```
- [ ] **Expected:** identical.

### 1.5 Paths with spaces

- [ ] **Steps:** copy the save to a folder whose name has a space and run HV.2 there with the path in quotes.
- [ ] **Expected:** the same result.

## Section 2: the ledger and revert

### 2.1 The ledger

- [ ] **Steps:** after an edit, `python -m json.tool Camp__set-sex.edits.json`
- [ ] **Expected:** one entry with the edit's name, `"pack": "edits"`, the resolved id under `params`, the change's offsets and bytes (base64), and two hashes.

### 2.2 A second edit carries the first

- [ ] **Steps:** edit `Camp__set-sex.ck3` again (another character). Read the new ledger.
- [ ] **Expected:** two entries, in order.
- [ ] `revert all --yes` on that file gives the original's contents (compare with HV.4's hash command).

### 2.3 revert is refused after the game saved (MANUAL)

- [ ] **Steps:** load an edited copy in the game, save over it, then run `revert` on it.
- [ ] **Expected:** refused: the save has changed since its last edit.

## Section 3: backups

Use a scratch config so your own is untouched.

**cmd.exe**: `set CK3SM_CONFIG=%TEMP%\ck3edit\config.toml`
**PowerShell**: `$env:CK3SM_CONFIG = "$env:TEMP\ck3edit\config.toml"`
**POSIX**: `export CK3SM_CONFIG=/tmp/ck3edit/config.toml`

The folder of that file also holds the tool's records, so they stay in the scratch folder too.

### 3.1 `--no-bak`

- [ ] **Steps:** on a fresh copy, `ck3update edit Camp3.ck3 set-sex <id> male --in-place --no-bak --yes`
- [ ] **Expected:** no `Camp3.bak.ck3`, and one line saying the original is gone.

### 3.2 `backup = false` in the config

- [ ] **Steps:** put `backup = false` in the scratch config; run `--in-place` without `--bak`/`--no-bak`; then again with `--bak`.
- [ ] **Expected:** no backup the first time; a backup with `--bak`.

## Section 4: ironman, binary saves, `--dangerous`

### 4.1 `ironman-off` on an ordinary save

- [ ] **Steps:** `ck3update edit Camp.ck3 ironman-off`
- [ ] **Expected:** "nothing to change (ironman is already off)", nothing written.

### 4.2 A binary save is refused (if you have an ironman save)

- [ ] **Steps:** `ck3update edit <ironman save copy> set-sex 1 male`
- [ ] **Expected:** refused as a binary save, naming its header kind. Nothing written.

### 4.3 `update --dangerous` (optional)

- [ ] **Steps:** `ck3update status <copy> --dangerous` on a save your packs' version spans leave out.
- [ ] **Expected:** NOTES names each pack that runs outside its span. Without the flag those packs are skipped.

## What the automated tests DON'T cover

- **The game.** No test loads a save in the game. Whether the edited character looks right is HV.3.
- **A real save's size.** The tests use saves of a few kilobytes; the character lookup takes 9 to 15 seconds on a 240 MB save.
- **The terminal question.** Tests replace the terminal check; the real prompt, Enter, and Ctrl-C are 1.1.
- **Readability.** Column alignment, a 30-row candidate list, long house names, names with non-English letters as the save spells them.
- **Windows paths** with spaces, and a save open in another program.
- **Names in other naming customs.** The words skipped in a name ("nic", "mac", "of", ...) are a short list.
- **A real ironman save.** None was available; 4.2 uses one if you have it.

## Reporting issues found

1. Note the section and step number.
2. Capture the exact command and its output.
3. Keep the ledger file and the output save (not your original).
4. File an issue naming this checklist and the version from `ck3update --version`.

## Cleanup

Delete the scratch folder, and the test copy you placed in the game's save folder.

**cmd.exe**: `cd /d %TEMP% && rmdir /s /q %TEMP%\ck3edit && set CK3SM_CONFIG=`
**PowerShell**: `Set-Location $env:TEMP; Remove-Item -Recurse "$env:TEMP\ck3edit"; Remove-Item Env:\CK3SM_CONFIG -ErrorAction SilentlyContinue`
**POSIX**: `cd /tmp && rm -r /tmp/ck3edit; unset CK3SM_CONFIG`

To reset between sections without removing the copy, delete everything in the folder except `Camp.ck3`.
