# Human Test Checklist: the plan's layout, the progress spinner and the timings

**Target version:** 0.3.19
**Ships with commit:** v0.3.19 (status layout, spinner, timings, fail-early, `[display]` settings)
**Companion automated tests:** 51 tests in `tests/test_status_layout.py` (27 functions), plus the plan tests in `tests/test_update.py`, `tests/test_detect.py` and `tests/test_record.py` updated for the new layout; 23 behaviour mutations of the new code each turn a test red.

## What this is

`ck3update status` and `ck3update update` print their plan as blocks, show a spinner while they read and judge a save, say how long it took, and stop early when the plan is already refused. The tests check the text the tool produces; they cannot see a real console. This checklist is for a person at a Windows console (Windows Terminal and the old console window both, if you can), and covers what only eyes can judge: does it read well, does the spinner behave, does a narrow window stay tidy.

## Prerequisites

1. `ck3update --version` prints 0.3.19.
2. A scratch folder with a **copy** of an old save, and a scratch settings file, so nothing here touches your real saves or your real `config.toml`:

   **cmd.exe**:
   ```cmd
   mkdir %TEMP%\ck3-checklist
   copy "<an old save>.ck3" %TEMP%\ck3-checklist\Old.ck3
   set CK3SM_CONFIG=%TEMP%\ck3-checklist\config.toml
   cd /d %TEMP%\ck3-checklist
   ```

   **PowerShell**:
   ```powershell
   New-Item -ItemType Directory -Force "$env:TEMP\ck3-checklist" | Out-Null
   Copy-Item "<an old save>.ck3" "$env:TEMP\ck3-checklist\Old.ck3"
   $env:CK3SM_CONFIG = "$env:TEMP\ck3-checklist\config.toml"
   Set-Location "$env:TEMP\ck3-checklist"
   ```

   **POSIX**:
   ```bash
   mkdir -p /tmp/ck3-checklist
   cp "<an old save>.ck3" /tmp/ck3-checklist/Old.ck3
   export CK3SM_CONFIG=/tmp/ck3-checklist/config.toml
   cd /tmp/ck3-checklist
   ```

3. For the refused case you need at least two saves in your save folder written by the installed game on the old save's date (two copies of one reference save named `MIGRATE_TEST__...` will do). For the full case you need one reference save to name with `--reference`.
4. **Reset between sections:** delete the scratch `config.toml` (`del config.toml` / `Remove-Item config.toml` / `rm -f config.toml`) so the defaults apply again.

## High-Value Verification (~5 minutes)

### HV.1: the refused plan answers at once

Validates: fail-early, and the verdict's time.

- [ ] **Steps:** `ck3update status Old.ck3` (with two candidate reference saves present, see Prerequisites 3)
- [ ] **Expected:** `REFUSED  1 reason(s), below; nothing is written  (0.x s)`, in under a few seconds; `DETECTORS  did: not run: the plan is refused (fail early); ...`; the refusal at the end names the candidates and the fix `--reference`.
- [ ] **Why this matters:** before 0.3.19 this case read and judged the whole save (minutes on a large one) only to refuse.

### HV.2: the default layout reads cleanly

Validates: the defaults (`flow`, gap 2, `compact`).

- [ ] **Steps:** `ck3update status Old.ck3` with no scratch `config.toml`.
- [ ] **Expected:** no blank lines; `SAVE`'s field names right-aligned under each other with the colons in one column; `GAME  version:` two spaces after `GAME`; a one-line block after a wider one (`GAP` after `RECORD`, `PACKS` after `REFERENCE`) keeps the wider one's column instead of shrinking.
- [ ] **Why this matters:** this is the layout every player sees first.

### HV.3: the spinner during a full run

Validates: the spinner, the stages, and that it cleans up.

- [ ] **Steps:** `ck3update status Old.ck3 --reference "<a reference save>" --transplant auto`
- [ ] **Expected:** one line on the console redrawn in place: `reading the whole save (NN.N MB compressed)`, then `checking R1 opinions-converging (1 of N)` and onward with the seconds counting; the line is gone when the plan prints (no leftover characters); the plan's `DETECTORS` block shows `read:` and `judged: N step(s) in X s; slowest ...`.
- [ ] **Why this matters:** a run of a minute or more with no sign of life looks hung.

### HV.4: plain output for pasting

Validates: `--plain`, `NO_COLOR`.

- [ ] **Steps:** `ck3update status Old.ck3 --plain`, then the same with `NO_COLOR` set and no `--plain`:

  **cmd.exe**: `set NO_COLOR=1` then the command; `set NO_COLOR=` after.
  **PowerShell**: `$env:NO_COLOR = "1"` then the command; `Remove-Item Env:\NO_COLOR` after.
  **POSIX**: `NO_COLOR=1 ck3update status Old.ck3`
- [ ] **Expected:** both have no colour and no spinner; the text is the same in both apart from the time in the verdict.
- [ ] **Why this matters:** output pasted into an issue must read as it did on screen.

### HV.5: a setting changes the layout and survives

Validates: `[display]`, and that the tool's own commands keep it.

- [ ] **Steps:** write `config.toml` with `[display]` and `align = "global"`; run status; then `ck3update disable R21`; view the file (`type config.toml` / `Get-Content config.toml` / `cat config.toml`); run status again.
- [ ] **Expected:** with `global` every colon in the output is in one column; after `disable` the file still holds the `[display]` table and `disabled = ["R21"]`; status still shows the `global` layout.
- [ ] **Why this matters:** a layout choice that a later command silently erases is worse than none.

## Section 1: the layout settings (~10 minutes)

### 1.1 Each alignment

- [ ] **Steps:** for each of `align = "flow"`, `"global"`, `"blocks"`: set it in `config.toml`, run `ck3update status Old.ck3 --plain`.
- [ ] **Expected:** matches the side-by-side example in `docs/config.md` for the blocks it shows; `blocks` pads every header to the longest header (`REFERENCE`).

### 1.2 The gap

- [ ] **Steps:** `gap = 1`, then `gap = 4`, under `flow`.
- [ ] **Expected:** the space between `GAME` and `version:` is 1, then 4; nothing else changes shape.

### 1.3 Blank spacing

- [ ] **Steps:** `spacing = "blank"`.
- [ ] **Expected:** one blank line between blocks, after the verdict, and before the refusal; nothing else changes.

### 1.4 Bad values

- [ ] **Steps:** in turn: `gap = 0`, `gap = 9`, `gap = "2"`, `spacing = "tight"`, `align = "left"`.
- [ ] **Expected:** each stops the command with exit code 1 and a message naming the full path of `config.toml` and the setting (`[display] gap must be a whole number of spaces from 1 to 8`, `[display] align must be one of "blocks", "global", "flow"`, ...). Nothing else runs.

## Section 2: width and wrapping (~5 minutes)

### 2.1 A narrow window

- [ ] **Steps:** make the console about 60 columns wide; run `ck3update status Old.ck3`.
- [ ] **Expected:** no line runs past the edge; a long value (the game path, a note) continues on the next line under its own value column, never under a header; the patches table keeps its columns and a long reason moves to its own line under the patch name.

### 2.2 A wide window

- [ ] **Steps:** make the console wider than 120 columns.
- [ ] **Expected:** lines stop at 120 characters; nothing stretches to fill the window.

### 2.3 COLUMNS

- [ ] **Steps:** set `COLUMNS=80` (`set COLUMNS=80` / `$env:COLUMNS = "80"` / `export COLUMNS=80`), run status piped to a file (`ck3update status Old.ck3 > out.txt`), view it; unset `COLUMNS` after.
- [ ] **Expected:** the file's lines are at most 80 characters; with `COLUMNS` unset a piped run uses 120.

## Section 3: the spinner (~10 minutes)

### 3.1 Windows Terminal and the old console window

- [ ] **Steps:** run HV.3 in Windows Terminal, then in a plain `cmd.exe` window (conhost).
- [ ] **Expected:** in both, the spinner's star-like frames turn in place; if a console cannot draw them it falls back to `| / - \`; never a row of garbled characters.

### 3.2 Off where it should be

- [ ] **Steps:** run status with `-q`; with `--plain`; with `NO_COLOR` set; piped (`ck3update status Old.ck3 2> err.txt`, then view `err.txt`).
- [ ] **Expected:** no spinner in any of them; `err.txt` holds no spinner frames and no carriage-return redraws.

### 3.3 Ctrl-C mid-run

- [ ] **Steps:** start HV.3 and press Ctrl-C while the spinner shows `checking ...`.
- [ ] **Expected:** the spinner line is erased before Python's interrupt message prints; the prompt comes back; no spinner keeps drawing afterwards.

### 3.4 Resizing mid-run

- [ ] **Steps:** start HV.3 and narrow the window while it runs.
- [ ] **Expected:** at worst one stale line of spinner text; it never scrolls a column of spinner lines down the window.

## Section 4: times and status without a save (~3 minutes)

### 4.1 The times add up

- [ ] **Steps:** after HV.3, read the verdict's time and the `DETECTORS` block.
- [ ] **Expected:** the verdict's time is at least `read` plus `judged`; `slowest` names three rule ids with their seconds in decreasing order.

### 4.2 Status with no save

- [ ] **Steps:** `ck3update status`
- [ ] **Expected:** a `GAME` block (version, path, how it was found) and a `SAVES` block (folder, count), in the same layout as the plan.

## What the automated tests DON'T cover

- How the spinner looks in a real console (Windows Terminal, conhost, a code-page-437 console), and whether its frames draw at all
- Ctrl-C while the spinner draws, and resizing the window mid-run
- Whether the layout reads well to a person: the tests check columns, not taste
- The real time of a full run on a large save (the fixtures are small)
- Colour: the tests compare text with the colours stripped

## Reporting issues found

1. Note the section and step number.
2. Capture the exact command and its output (`--plain` for pasting).
3. Note the console (Windows Terminal or cmd.exe window) and its width.
4. File an issue referencing this checklist and 0.3.19.

## Cleanup

**cmd.exe**: `set CK3SM_CONFIG=` then `cd /d %USERPROFILE%` and `rmdir /s /q %TEMP%\ck3-checklist`
**PowerShell**: `Remove-Item Env:\CK3SM_CONFIG`, `Set-Location ~`, `Remove-Item -Recurse "$env:TEMP\ck3-checklist"`
**POSIX**: `unset CK3SM_CONFIG; cd ~; rm -rf /tmp/ck3-checklist`

Your real `config.toml` and your saves were never touched.
