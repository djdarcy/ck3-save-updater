# Human Test Checklist: names as the game shows them, across the edits

**Target version:** 0.5.33 (the work shipped in 0.5.29 to 0.5.32; 0.5.33 documents it)
**Ships with commit:** v0.5.33 (docs and this checklist)
**Companion automated tests:**
- `tests/test_names.py` (21)
- `tests/test_display_names.py` (16)
- `tests/test_cli_output_encoding.py` (14)
- new cases in `tests/test_characters.py` (7), `tests/test_edit_eminent.py` (2), `tests/test_edit_set_faith.py` (1) and `tests/test_edit_doctrines.py` (2)

## What this is

The edits now read names the way the game shows them. That covers characters, holy sites, faiths, rites, tenets and doctrines. Accents never matter, several names are separated by commas, and doctrines may carry their group ("Pilgrimage Attitude: Encouraged"). A report holding an accented name no longer crashes when its output is piped. The automated tests use synthetic saves and a fake game folder. This checklist runs the same things on a real save with the real game install, where the names come from the game's own language files. Anyone with Crusader Kings III 1.20 and a text save can run it.

## Prerequisites

1. Crusader Kings III 1.20 installed through Steam, or its `game` folder at a known path.
2. `ck3update` 0.5.33 or later (`ck3update --version`).
3. A **copy** of a 1.20 text save, in a scratch folder, called `Test.ck3` below. Every step here is `--dry-run` or a read, so nothing is written, but still use a copy.
4. Pick a character in the save whose name has an accent, or whose parent's name does; any Irish, Norse or Slavic family works. Note their id.

Make the copy (pick your shell):

- **cmd.exe**: `mkdir %TEMP%\names-test && copy "<your save>.ck3" %TEMP%\names-test\Test.ck3 && cd /d %TEMP%\names-test`
- **PowerShell**: `New-Item -ItemType Directory -Force "$env:TEMP\names-test" | Out-Null; Copy-Item "<your save>.ck3" "$env:TEMP\names-test\Test.ck3"; Set-Location "$env:TEMP\names-test"`
- **POSIX**: `mkdir -p /tmp/names-test && cp "<your save>.ck3" /tmp/names-test/Test.ck3 && cd /tmp/names-test`

## High-Value Verification (~5 minutes)

### HV.1 A character by the name the game shows, with no accents typed

- [ ] **Steps:** `ck3update edit Test.ck3 set-sex "<first name without accents> <parent's first name without accents>" female --dry-run`
- [ ] **Expected:** the right character is found. The target line prints the names with their accents, as the game shows them, not keys like `GabrA_n`.
- [ ] **Why this matters:** the save stores names as keys, and before 0.5.32 an accented name could not be found at all.

### HV.2 Commas take multi-word names

- [ ] **Steps:** `ck3update edit Test.ck3 set-eminent-holy-sites "<a faith>" "<two-word holy site>, <another site>" --dry-run`, where the faith holds both sites.
- [ ] **Expected:** one `change at` line, and the target line lists the sites by the names the game shows.
- [ ] **Why this matters:** before, "Bodh Gaya" split into two unknown names.

### HV.3 A doctrine with its group, and a shared name refused

- [ ] **Steps:** `ck3update edit Test.ck3 set-doctrines "<a faith>" "+Pilgrimage Attitude: Encouraged" --dry-run`, then the same with `"+Encouraged"`.
- [ ] **Expected:** the first plans the change (or says the faith already has it). The second is refused, listing "Monasticism: Encouraged" and "Pilgrimage Attitude: Encouraged" with their keys.
- [ ] **Why this matters:** eight doctrine names are shared across groups, and the tool must never guess between them.

### HV.4 A piped report with an accented name does not crash

- [ ] **Steps:** run HV.1 again with the output redirected. In cmd.exe and PowerShell use `> out.txt`; in POSIX use `> out.txt`. Then view the file: `type out.txt`, `Get-Content out.txt` or `cat out.txt`.
- [ ] **Expected:** the command finishes normally. On Windows the file holds the names without accents (for example "Gabran"), not an error.
- [ ] **Why this matters:** a cp1252 pipe used to end the run with `'charmap' codec can't encode character`.

### HV.5 Without the game folder, keys still work

- [ ] **Steps** (pick your shell): `set CK3_GAME_DIR=none` / `$env:CK3_GAME_DIR = "none"` / `export CK3_GAME_DIR=none`, then `ck3update edit Test.ck3 set-eminent-holy-sites "<faith>" "<site key>, <site key>" --dry-run`, and then the same with a name that exists only on screen.
- [ ] **Expected:** the keys work. The on-screen name fails, saying "the game's display names need the game folder: set CK3_GAME_DIR".
- [ ] Unset afterwards: `set CK3_GAME_DIR=` / `Remove-Item Env:\CK3_GAME_DIR` / `unset CK3_GAME_DIR`.

## Section 1: characters

- [ ] **1.1 Ligatures:** for a name with Æ, Ø, Ł or Þ, type it with Ae, O, L or Th (e.g. "Aelfweard"). It is found.
- [ ] **1.2 A multi-word house:** narrow by a house whose name is two words, as shown in game (e.g. "Ui Neill"). It narrows.
- [ ] **1.3 The key still works:** type the save's own key for a first name (a candidate list shows it when there is no game folder). It is found.
- [ ] **1.4 Every character edit:** run 1.1's query with `artifacts`, `events` and `set-faith` too (dry runs or views). Each finds the same character.
- [ ] **1.5 Candidate lists:** run a first name several characters share. The list prints first names, parents, houses and titles as the game shows them.

## Section 2: faith names

- [ ] **2.1 A rite by its display name:** `set-faith <id> "Ásatrú" --dry-run` and `"asatru"`. Both find the rite, and the report shows "Ásatrú".
- [ ] **2.2 A shared holy-site name:** on a faith holding one of the two Carthages, `set-eminent-holy-sites <faith> "Carthage, <another site>" --dry-run`. It picks the faith's own. On a faith holding neither, it is refused, listing both with their keys.
- [ ] **2.3 Tenets by name:** `set-doctrines <faith> "-<a tenet it has>, +<another tenet>" --dry-run`, written as the game shows them. It reads "tenet <old> -> <new>".
- [ ] **2.4 A misspelling:** a holy site or tenet with one letter wrong. It is refused, with the nearest names offered.

## What the automated tests DON'T cover

- The real localisation files: a game update could rename a key pattern. Only a run against the real game shows the names still resolve.
- How the output reads in a real console and in a redirected file on Windows.
- How long the first edit takes while it loads the game's names (about half a second on the developer's machine).
- Names from mods: mods may add their own localisation, which this does not read.
- Other languages: the tool reads English names.

## Reporting issues found

Note the step, copy the command and its output, keep `Test.ck3`, and file an issue naming this checklist and the `ck3update --version`.

## Cleanup

Delete the scratch folder: `rmdir /s /q %TEMP%\names-test` / `Remove-Item -Recurse "$env:TEMP\names-test"` / `rm -rf /tmp/names-test`, and unset `CK3_GAME_DIR` if HV.5 set it.
