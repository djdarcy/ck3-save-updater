# Human Test Checklist: update asks before it runs, and reuses a status run's checks

**Target version:** 0.4.30
**Ships with commit:** TBD (v0.4.30)
**Companion automated tests:** 4 in `tests/test_update.py` (the `--ask` tests) and 7 in `tests/test_plan_cache.py`. The full suite count is in the commit message.

## What this is

What a person runs to see 0.4.30 for themselves. Two things changed.

`ck3update update <save>` now prints its plan and asks "Run the update now? [y/N]" before it changes anything. It asks only when a person is at a terminal. A script, a pipe, or output sent to a file runs without asking. `--no-ask` never asks. `--ask` asks even when it would not by default.

`update` also reuses the checks of a `status` run made just before it on the same save. Only checks that said a step is needed are reused. Anything else is checked again. A different save, a changed option, or a new version of the tool means a fresh run.

The automated tests fake the terminal. This checklist uses real ones: cmd.exe, PowerShell, and Git Bash each report "is this a terminal?" in their own way, and that is what the tests cannot see.

## Prerequisites

1. Python 3.10 or newer, with this version installed (`ck3update --version` shows 0.4.30).
2. A save from an older version of the game. **Use a copy, never your only save.** Name the copy `MIGRATE_TEST__ask.ck3` so it is easy to tell apart and to clean up.
3. Your game folder, if the tool does not find it by itself (`--game-dir`).

**Your save folder:**
- cmd.exe: `%USERPROFILE%\Documents\Paradox Interactive\Crusader Kings III\save games`
- PowerShell: `"$env:USERPROFILE\Documents\Paradox Interactive\Crusader Kings III\save games"`
- POSIX: `~/.local/share/Paradox Interactive/Crusader Kings III/save games` (Linux)

Run the commands below from that folder. The tool never changes the save you name. It writes `MIGRATE_TEST__ask__updated__<version>.ck3` beside it.

**Reset between sections:** delete the `__updated__` file and its report, and nothing else.
- cmd.exe: `del "MIGRATE_TEST__ask__updated__*"`
- PowerShell: `Remove-Item "MIGRATE_TEST__ask__updated__*"`
- POSIX: `rm -f MIGRATE_TEST__ask__updated__*`

**To start the cache empty:** `ck3update cache clear` (the same in every shell).

## High-Value Verification (~5 minutes, plus one update's run time)

### HV.1 -- update asks at a terminal, and "no" changes nothing

Validates: the default question, and that only a yes runs.

- [ ] **Steps** (same in every shell):
  1. `ck3update update MIGRATE_TEST__ask.ck3`
  2. Read the plan. At "Run the update now? [y/N]", press Enter.
- [ ] **Expected:** the plan prints first, then the question. After Enter: "not run: nothing written". No `__updated__` file appears.
- [ ] **Why this matters:** a player reading the plan must be able to back out with nothing written.

### HV.2 -- "y" runs it

- [ ] **Steps:** run HV.1 again and type `y`, then Enter.
- [ ] **Expected:** the update runs and ends with a "wrote:" line naming the `__updated__` file.
- [ ] **Why this matters:** the one-command flow (read, then run) must actually run.

### HV.3 -- --no-ask never asks

- [ ] **Steps:** reset, then `ck3update update MIGRATE_TEST__ask.ck3 --no-ask`
- [ ] **Expected:** no question. The update runs straight through.
- [ ] **Why this matters:** power users and scripts must not hang on a prompt.

### HV.4 -- update after status reuses the checks

- [ ] **Steps:** reset and `ck3update cache clear`, then:
  1. `ck3update status MIGRATE_TEST__ask.ck3` and note the DETECTORS block's "judged" line (its time).
  2. `ck3update update MIGRATE_TEST__ask.ck3 --no-ask`
- [ ] **Expected:** step 2's DETECTORS block says "reused N verdict(s) of the run at HH:MM on this same save". Its "judged" time is near 0 s, and its READY line's time is far shorter than step 1's. Measured on a 222 MB save: 123.7 s for `status`, 20.5 s for `update`'s plan.
- [ ] **Why this matters:** this is the waiting it saves. A player who checks first should not wait twice.

### HV.5 -- a changed option means a fresh run

- [ ] **Steps:** reset, run HV.4 step 1 again, then `ck3update update MIGRATE_TEST__ask.ck3 --no-ask --face-changes none`
- [ ] **Expected:** no "reused" in DETECTORS. Every step is checked again and takes its normal time.
- [ ] **Why this matters:** a reused check made with other options could skip a step that is needed.

## Section 1: when update asks

### 1.1 Output sent to a file runs without asking

- [ ] **Steps:**

  **cmd.exe**:
  ```cmd
  ck3update update MIGRATE_TEST__ask.ck3 > "%TEMP%\ask_out.txt"
  type "%TEMP%\ask_out.txt"
  ```

  **PowerShell**:
  ```powershell
  ck3update update MIGRATE_TEST__ask.ck3 > "$env:TEMP\ask_out.txt"
  Get-Content "$env:TEMP\ask_out.txt"
  ```

  **POSIX**:
  ```bash
  ck3update update MIGRATE_TEST__ask.ck3 > /tmp/ask_out.txt
  cat /tmp/ask_out.txt
  ```
- [ ] **Expected:** no question on screen. The run completes, and the file holds the plan and the "wrote:" line.

### 1.2 A pipe runs without asking

- [ ] **Steps:** reset, then `ck3update update MIGRATE_TEST__ask.ck3 | more` (the same in every shell).
- [ ] **Expected:** no question. The output pages through `more`, and the update runs.

### 1.3 --ask with no terminal to answer from refuses

- [ ] **Steps:** reset, then:
  - cmd.exe: `ck3update update MIGRATE_TEST__ask.ck3 --ask < NUL`
  - PowerShell: `$null | ck3update update MIGRATE_TEST__ask.ck3 --ask`
  - POSIX: `ck3update update MIGRATE_TEST__ask.ck3 --ask < /dev/null`
- [ ] **Expected:** "--ask needs a terminal to answer from; not run". No `__updated__` file.

### 1.4 --ask while the output goes to a file still asks

- [ ] **Steps:** reset, then the 1.1 command with `--ask` added.
- [ ] **Expected:** the question shows on screen, even though the plan went to the file. Press Enter. Nothing is written.

### 1.5 --dry-run never asks

- [ ] **Steps:** `ck3update update MIGRATE_TEST__ask.ck3 --dry-run`
- [ ] **Expected:** the plan with each patch's counts. No question, and nothing written.

### 1.6 The question reads well

- [ ] **Check:** in each shell, the question sits on its own line after the plan, the cursor waits after "[y/N] ", and typing `Y` or `yes` also runs. Ctrl-C at the question stops with nothing written.

## Section 2: the reused checks

### 2.1 A different save in the same file is never reused

- [ ] **Steps:** run `status` on `MIGRATE_TEST__ask.ck3`. Then copy a *different* old save over `MIGRATE_TEST__ask.ck3` and run `update --no-ask` on it.
- [ ] **Expected:** no "reused". The tool reads the save's content, not only its name.

### 2.2 The cache can be listed and emptied

- [ ] **Steps:** `ck3update cache where`, then `ck3update cache clear`
- [ ] **Expected:** `cache clear` says "removed N cached index(es), ... MB, and N saved plan verdict file(s), ... KB, from <folder>". A second `cache clear` reports 0 of each.

### 2.3 The switch turns it off

- [ ] **Steps:** open your config file, creating it if it does not exist. It is `%APPDATA%\ck3-save-migrator\config.toml` on Windows (PowerShell: `"$env:APPDATA\ck3-save-migrator\config.toml"`), and `~/.config/ck3-save-migrator/config.toml` elsewhere. Add the lines below, then repeat HV.4.
  ```toml
  [cache]
  plans = false
  ```
- [ ] **Expected:** no "reused", and the `plans` folder under the cache folder stays empty.
- [ ] **Reset:** remove the two lines.

### 2.4 Checks older than a day are not reused

- [ ] **Optional:** run `status`, wait more than 24 hours, run `update --no-ask`.
- [ ] **Expected:** no "reused".

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| asks by default at a (faked) terminal; only a yes runs; `--no-ask` and scripts never ask; `--ask` without a terminal refuses | `tests/test_update.py` | 4 |
| only "needed" checks reused; a cached "done" judged again; a changed option, a different save, another build of the tool each mean a fresh run; the switch off; `cache clear` | `tests/test_plan_cache.py` | 7 |

Each of the 11 was shown to turn red when the behaviour it guards was broken on purpose (12 mutants, all caught).

## What the automated tests DON'T cover

- How cmd.exe, PowerShell, and Git Bash (mintty) report a terminal. Git Bash under mintty may report no terminal to Python, so `update` may not ask there by default. Note what you see.
- The question's look in a real console, and Ctrl-C at the prompt.
- Real time saved on a large save (HV.4).
- The cache folder on a real machine, and its 24-hour expiry.

## Reporting issues found

1. Note the section and step number, and the shell.
2. Capture the exact command and its output.
3. File an issue on GitHub referencing this checklist and version 0.4.30.

## Cleanup

- Delete `MIGRATE_TEST__ask.ck3` and every `MIGRATE_TEST__ask__updated__*` file (see Reset above).
- Delete the output files from 1.1 (`%TEMP%\ask_out.txt` / `$env:TEMP\ask_out.txt` / `/tmp/ask_out.txt`).
- `ck3update cache clear`.
- Remove `plans = false` from your config if you added it.
