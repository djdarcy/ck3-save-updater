# Human Test Checklist: an update that does not ask skips the checks, and explains its counts

**Target version:** 0.5.0 (pending the maintainer's word on the number)
**Ships with commit:** TBD
**Companion automated tests:** `tests/test_update.py` (2 new, 1 changed), `tests/test_patches_failures.py` (2 new), `tests/test_deadtitles.py` (10 new), `tests/test_step_findings.py` (3 new), `tests/test_dna.py` (1 new), `tests/test_requirements.py` (3 new, 2 changed). The full suite count is in the commit message.

## What this is

What a person runs to see this release for themselves. The changes:
- **Faster when not asking:** an `update` that runs without asking skips the checks that only describe the plan, and each patch's line after the run says what it does.
- **Early stop:** a failed patch stops the update at once.
- **R15:** its line in `status` counts every title it will settle, and a 1.8 save needs no old game for it (a built-in copy of the 1.8.2 map's titles).

The tests check the text and the logic; this checklist checks how it reads, and the time it saves, on a real save.

## Prerequisites

1. This version installed (`ck3update --version`), or run as `python -m ck3_save_migrator` from the repository.
2. A copy of an old save (1.8 or later), named `MIGRATE_TEST__speed.ck3` in your save folder. **Never your only save.**
3. A reference save for its date, if the save is from before the 1.13 map rework (see the README).

**Reset between steps:** delete the outputs, and nothing else.
- cmd.exe: `del MIGRATE_TEST__speed__*`
- PowerShell: `Remove-Item MIGRATE_TEST__speed__*`
- POSIX: `rm -f MIGRATE_TEST__speed__*`

## High-Value Verification (~30 minutes, mostly waiting)

### HV.1 -- without asking: no checks beforehand, explained counts after, the same save

- [ ] **Steps:**
  1. `ck3update update MIGRATE_TEST__speed.ck3 --no-ask -o MIGRATE_TEST__speed__noask.ck3`
  2. `ck3update update MIGRATE_TEST__speed.ck3 -o MIGRATE_TEST__speed__ask.ck3`, then answer `y`.
- [ ] **Expected:**
  - Run 1's DETECTORS block says "not run: update is not asking first, so it does not judge the steps beforehand; each patch's counts follow the run".
  - Each line under "rules applied" ends with "-- " and what the patch does, e.g. `R3 title-names matched 12,702 edited 29,000 -- move inline title name/adj/pre/article into title_name_data`.
  - The "gamestate sha" line is the same in both runs.
  - Run 1 is faster: a minute or two on a large save.
- [ ] **Why this matters:** skipping the checks must change only the time and the wording, never the save.

### HV.2 -- asking still shows the full plan first

- [ ] **Steps:** reset, then `ck3update update MIGRATE_TEST__speed.ck3` at a terminal. Press Enter at the question.
- [ ] **Expected:** PATCHES lines with "needed: ..." details, DETECTORS "judged each built-in step", the question "Run the update now? [y/N]". Enter writes nothing.
- [ ] **Why this matters:** a person deciding whether to run sees the whole plan first.

### HV.3 -- a dry run is a full preview

- [ ] **Steps:** `ck3update update MIGRATE_TEST__speed.ck3 --dry-run`
- [ ] **Expected:** the judged plan ("needed: ..." lines), then each patch's counts without the "-- " descriptions. Nothing is written.

### HV.4 -- a failing patch stops at once

- [ ] **Steps:** make a folder `failpack` with two files.

  `failpack\pack.toml`:
  ```toml
  format = 1
  id = "fail"
  title = "fail"
  order = ["E1"]
  ```

  `failpack\E1-x\patch.toml`:
  ```toml
  format = 1
  id = "E1"
  name = "must-find"
  title = "t"
  since = "1.20"

  [[edit]]
  path = "nothing_here"
  op = "delete_key"
  key = "not_there"
  expect = 1
  ```

  Then run `ck3update update MIGRATE_TEST__speed.ck3 --no-ask --pack failpack -o MIGRATE_TEST__speed__fail.ck3` and read the exit code:
  - cmd.exe: `echo %ERRORLEVEL%`
  - PowerShell: `$LASTEXITCODE`
  - POSIX: `echo $?`
- [ ] **Expected:** "ERROR: patch E1 (must-find) failed: ...", then "1 patch(es) failed; the update stopped there, N later patch(es) not run; nothing written". Exit code 5. No `MIGRATE_TEST__speed__fail.ck3`.
- [ ] **Why this matters:** a failure no longer costs minutes of patches whose work is thrown away.

### HV.5 -- R15's line in status

- [ ] **Steps:** `ck3update status MIGRATE_TEST__speed.ck3` (with `--old-game-dir` pointing at the save's own game version, if you have one).
- [ ] **Expected:** R15's line reads "needed: N titles to settle by place (removed by the game, or baronies it moved)", with examples by kind (dead, moved, follows). For a 1.8 save the count is the same with and without `--old-game-dir` (HV.6). For a save from another version, without `--old-game-dir` it says "unknown: no built-in old map covers a 1.N save; give --old-game-dir ...".

### HV.6 -- a 1.8 save needs no old game for R15

- [ ] **Steps:** with a 1.8 save and its reference save, run the update twice, once with `--old-game-dir` (the 1.8 game folder, if you have it) and once without:
  1. `ck3update update MIGRATE_TEST__speed.ck3 --reference <reference> --no-ask -o MIGRATE_TEST__speed__nomap.ck3`
  2. `ck3update update MIGRATE_TEST__speed.ck3 --reference <reference> --old-game-dir <1.8 game folder> --no-ask -o MIGRATE_TEST__speed__map.ck3`
- [ ] **Expected:**
  - Run 1's NOTES say "R15's old map: built-in table (Crusader Kings III 1.8.2, names only)"; run 2's say "R15's old map: --old-game-dir (...)".
  - R15 runs in both ("rules applied" lists it with its counts).
  - The "gamestate sha" line is the same in both runs.
- [ ] **Why this matters:** most players have only the current game; without this, their removed and moved titles were left for the game to discard.

| the built-in old map: the script keeps exactly R15's tree; the shipped table equals the 1.8.2 game's (where those files are present); the choice of map (the table for 1.8, a given folder wins, none for other lines); R15's check and rule read it | `tests/test_deadtitles.py` | 7 |

Each was shown to fail when the behaviour it guards was broken on purpose (36 deliberate breakages in all, all caught; one needed a test added first).

## What the automated tests DON'T cover

- Whether the output reads well to a player: the new DETECTORS sentence, and the "-- description" lines in a narrow terminal.
- The real time saved on a large save.
- Saves from other campaigns and versions.

## Reporting issues found

Note the HV number, the shell, the command and its output, and file an issue referencing this checklist.
