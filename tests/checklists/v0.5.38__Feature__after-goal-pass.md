# Human Test Checklist: the after-goal pass, fields the game determines

**Target version:** 0.5.38 (the work shipped in 0.5.34 to 0.5.37; 0.5.38 adds this checklist)
**Ships with commit:** v0.5.38 (this checklist)
**Companion automated tests:**
- `tests/test_savefile.py`: 3 for uncompressed saves (0.5.34)
- `tests/test_rules_doctrine_fill.py` (3, 0.5.35)
- `tests/test_rules_head_determination.py` (6, 0.5.36)
- new cases in `tests/test_lint.py` (1) and `tests/test_lint_fields.py` (4), 0.5.36
- `tests/test_refmod_names.py` (6, 0.5.37)

## What this is

An updated save should say only what the game itself would say, and lint should name what stays unknown. Four releases moved the tool that way. The tool now reads a save the game wrote uncompressed, though it never writes one. A custom faith carried from an older version gets the doctrine groups added since, taken from the faith it came from. Each carried culture gets its head determination from its template. Lint explains every field it leaves unfilled, and it no longer warns about shapes the game writes itself. `reference-mod` takes the names the game shows for the ruler's culture, faith, house and title. The automated tests use synthetic saves and a fake game folder. This checklist runs the same paths on a real old save with the real game, and in the game itself. Anyone with Crusader Kings III 1.20 and an older campaign save can run it.

## Prerequisites

1. Crusader Kings III 1.20 installed, so `ck3update inspect` finds its `game` folder (or give `--game-dir`).
2. `ck3update` 0.5.37 or later (`ck3update --version`).
3. A **copy** of an older campaign save (1.8 to 1.19), ideally one with a custom faith and a culture made in play. It is called `Old.ck3` below. Work in a scratch folder. Never point a step at the original.
4. For section 1, an uncompressed save the game wrote (its first bytes are `SAV0100`). The game's own re-save from a soak run, made with `-debug_mode`, was one. Copy it as `Plain.ck3`. Skip section 1 if you have none.

Make the scratch folder and copies (pick your shell):

- **cmd.exe**: `mkdir %TEMP%\after-goal && copy "<your old save>.ck3" %TEMP%\after-goal\Old.ck3 && cd /d %TEMP%\after-goal`
- **PowerShell**: `New-Item -ItemType Directory -Force "$env:TEMP\after-goal" | Out-Null; Copy-Item "<your old save>.ck3" "$env:TEMP\after-goal\Old.ck3"; Set-Location "$env:TEMP\after-goal"`
- **POSIX**: `mkdir -p /tmp/after-goal && cp "<your old save>.ck3" /tmp/after-goal/Old.ck3 && cd /tmp/after-goal`

Then update the copy once. Most sections read its output, `New.ck3`, and its report:

```
ck3update update Old.ck3 -o New.ck3
```

(The same in every shell. Add `--reference <a 1.20 save on your date>` if your campaign needs the new map's regions; `status` says so.)

## High-Value Verification (~5 minutes)

### HV.1 A carried custom faith has its newer doctrine groups filled

Validates: R10's doctrine fill (0.5.35).

- [ ] **Steps:** find the custom faith's entry in the report, `New.report.json`, under `filled_doctrine_groups`:
  - **cmd.exe**: `findstr /c:"filled_doctrine_groups" New.report.json`
  - **PowerShell**: `Select-String -Path New.report.json -Pattern "filled_doctrine_groups"`
  - **POSIX**: `grep -o '"filled_doctrine_groups[^]]*]' New.report.json`
- [ ] **Expected:** one entry per group the old version lacked, each with a group, a doctrine and a source. The source is `origin faith <id>`, or a religion's default when the origin faith has none in that group. A faith made in 1.8 typically gets coronation, funeral, pilgrimage, theism, monasticism and sacraments.
- [ ] **Why this matters:** an empty group shows in the game as its first option, so a faith that never forbade pilgrimage showed "Forbidden".

### HV.2 In the game, the faith screen shows those doctrines

Validates: what the game makes of the filled groups. Manual: it needs the game.

- [ ] **Steps:** copy `New.ck3` into your save folder under a name of your own, such as `MIGRATE_TEST__after-goal.ck3`. Load it, open the custom faith's screen, and look at its doctrines.
- [ ] **Expected:** pilgrimage shows the origin faith's choice (for a Christian origin, "Encouraged"), not "Forbidden". Coronation and monasticism show the origin faith's choices too. Nothing in the panel is blank.
- [ ] **Why this matters:** the report says what was written. Only the game shows what a player sees.

### HV.3 Carried cultures have a head determination, once

Validates: R32 (0.5.36).

- [ ] **Steps:** look for R32's line in the update's output (`R32 head-determination matched N edited N`).
- [ ] **Expected:** N is about the number of cultures your old save carries with a template, and the line says it edited them. Then run `ck3update status New.ck3`. Its R32 line says "done: none found", because every culture with a template now has one.
- [ ] **Why this matters:** a culture without one has no way to pass on its headship, and a second copy of the field would be a malformed entry.

### HV.4 Lint says why a field is unfilled

Validates: lint's lists (0.5.36).

- [ ] **Steps:** `ck3update lint New.ck3`, then read the warning "entries carry the fields the game's own entries carry".
- [ ] **Expected:** each artifact line (type, wealth, quality, modifiers) ends with "no rule determines it (...)", naming the measurement. Coats of arms without an emblem appear only under the information line "fields left out on purpose or filled by the game". So do baronies without a coat and tax slots without a collector.
- [ ] **Why this matters:** a warning nobody can act on teaches players to ignore lint. A warning with its reason tells them it is known and why.

### HV.5 reference-mod by the names the game shows

Validates: name lookup for the ruler flags (0.5.37).

- [ ] **Steps:** `ck3update reference-mod --date 987.10.27 --character 900 --title d_munster --culture Irish --religion Insularism --house Briain --birth 941.1.1 --out .`
- [ ] **Expected:** it prints `--culture 'Irish' is irish`, then similar lines for `insular_celtic` and `house_british_isles_briain`. The key `d_munster` passes as it is, with no line. It writes `zz_ref_987_10_27`. The bookmark file `zz_ref_987_10_27/common/bookmarks/bookmarks/zz_ref.txt` holds the keys, not the names.
- [ ] **Why this matters:** players know the names on screen, not the keys in the files.

After these pass, the work shipped. The sections below cover the edges.

## Section 1: uncompressed saves (0.5.34)

### 1.1 Read

- [ ] **Steps:** `ck3update inspect Plain.ck3`, then `ck3update lint Plain.ck3`.
- [ ] **Expected:** both run. Inspect shows the header kind as text (00) and notes that this kind is read only.

### 1.2 Never written

- [ ] **Steps:** `ck3update update Plain.ck3 -o Out.ck3`
- [ ] **Expected:** it refuses at once, within a second, with a message saying kind 00 is read only and the tool writes only kind 02 saves. No `Out.ck3` is left behind. `ck3update edit Plain.ck3 set-sex <id> female` refuses the same way. (Before 0.5.38 the refusal came only at the write, after a couple of minutes of planning.)

## Section 2: doctrine groups (0.5.35)

### 2.1 Groups the faith already had are untouched

- [ ] **Steps:** note the custom faith's doctrines in the old game version (or from a screenshot of the old campaign), then open its faith screen in the loaded `New.ck3`. In `New.report.json`, the faith's `dropped_doctrines` names any old doctrine 1.20 no longer defines.
- [ ] **Expected:** every old doctrine 1.20 still defines shows as before. Only the groups listed under `filled_doctrine_groups` are new.

### 2.2 The base game's faiths are unchanged

- [ ] **Steps:** in the game, open a base faith such as Catholicism.
- [ ] **Expected:** its doctrines are the game's own. The fill touches only faiths carried as custom faiths.

## Section 3: cultures (0.5.36)

### 3.1 Cultures made in play are left alone, and lint says so

- [ ] **Steps:** in `ck3update lint New.ck3`, find the line for `culture_manager/cultures`.
- [ ] **Expected:** if the save has cultures made in play (hybrids, divergences), one line says how many lack `culture_template`, ending "no rule determines it". R32 did not invent a template or a head determination for them.

### 3.2 In the game, a carried culture shows its head determination

- [ ] **Steps:** in the loaded save, open a carried culture's screen (the Irish, say).
- [ ] **Expected:** it shows the same head determination as in a fresh 1.20 game, domain for most, herd for steppe and Arabian cultures.

## Section 4: lint's information lines (0.5.36)

### 4.1 A dead character filed among the living

- [ ] **Steps:** in `ck3update lint New.ck3`, look for "a dead character filed among the living keeps an old domain".
- [ ] **Expected:** if your save has such a character, he is listed there, as information. "Rulers whose domain lists titles they do not hold" no longer lists him as a warning. A save without one shows neither line for him.

## Section 5: reference-mod names (0.5.37)

Use a fresh `--out` folder for each step, or delete the `zz_ref_*` folder and `.mod` file in between, because the tool refuses to overwrite.

### 5.1 A shared name is refused with the candidates

- [ ] **Steps:** `ck3update reference-mod --date 987.10.27 --title Leinster --out .`
- [ ] **Expected:** exit code 1, and the message lists `Leinster (c_leinster), Leinster (d_leinster)` and asks for the one you mean. Nothing is written.
- [ ] **Also:** `--title Munster` is refused with three candidates: the German barony and county Münster, and the Irish duchy Munster. Accents are ignored, so they share a name. Does the message make the choice clear?

### 5.2 An unknown name gets the nearest

- [ ] **Steps:** `ck3update reference-mod --date 987.10.27 --culture Irsh --out .`
- [ ] **Expected:** refused, naming "Irish" among the nearest.

### 5.3 The religion is a rite

- [ ] **Steps:** `--religion Catholic`, then `--religion "Roman Rite"`.
- [ ] **Expected:** "Catholic" is refused, because 1.20 calls Catholicism's rite "Roman Rite". "Roman Rite" resolves to `roman_rite`. Is the refusal clear enough for a player who typed "Catholic"? Note what you think.

### 5.4 Accents, case and prefixes

- [ ] **Steps:** `--house "ua briuin seola"` (no accents, lower case).
- [ ] **Expected:** resolves to the house the game shows as "ua Briúin Seóla".

### 5.5 Without the game folder

- [ ] **Steps** (pick your shell):
  - **cmd.exe**: `set CK3_GAME_DIR=none` then `ck3update reference-mod --date 987.10.27 --character 900 --title d_munster --culture irish --religion insular_celtic --house house_british_isles_briain --birth 941.1.1 --out .`, then the same with `--culture Irish`. Finish with `set CK3_GAME_DIR=`.
  - **PowerShell**: `$env:CK3_GAME_DIR = "none"`, the same two commands, then `Remove-Item Env:\CK3_GAME_DIR`.
  - **POSIX**: `export CK3_GAME_DIR=none`, the same two commands, then `unset CK3_GAME_DIR`.
- [ ] **Expected:** the first, all keys, writes the mod. The second is refused. "Irish" is not a game key, and the message asks for `--game-dir`.

## What the automated tests DON'T cover

- What the game shows: the faith screen's doctrines, a culture's head determination, whether the game accepts the filled groups without complaint in its error log.
- Real game files at scale: the tests use a fake game with a handful of keys. The real tables hold about 16,000 titles, 600 houses and 150 rites, where a shared name is more likely than the tests show.
- Whether the messages read well to a player: "no rule determines it (...)", the "Catholic" refusal, the resolved-name lines.
- An uncompressed save from a real game session, as opposed to the soak's re-save.
- Older saves other than the founding campaign (1.8.1): another version may lack other groups or fields.

## Reporting issues found

1. Note the section and step.
2. Keep the exact command, its output and the exit code.
3. Keep `New.report.json` and the lint output.
4. File an issue that names this checklist and the version (`ck3update --version`).

## Cleanup

- Delete the scratch folder (`%TEMP%\after-goal`, `$env:TEMP\after-goal` or `/tmp/after-goal`).
- If you copied a test save into your save folder for HV.2, delete that copy. Your own saves were never touched.
- If you set `CK3_GAME_DIR` in 5.5, make sure it is unset.
