# Human Test Checklist: plots converted the way the game converts them

**Target version:** 0.4.24
**Ships with commit:** TBD (v0.4.24)
**Companion automated tests:** 1,167 passed (6 skipped) at the time of writing. This change: `tests/test_r29_scheme_thaw.py` (9, of them 3 new), `tests/test_r25_successor_keys.py` (23, of them 1 new), and the opt-in real-save test in `tests/test_rules.py` (`CK3_REAL_SAVES=1`), which now also checks the counts of R26 to R30.

## What this is

What a person runs to see 0.4.24 for themselves. Plots carried from an old save are now written the way the current game writes them after loading one, so the game no longer logs an error per plot. An artifact's old "+4 opinion with all vassals" now gives exactly +4. The automated tests check the save's text. This checklist checks the updated save's plots by hand, and what a player sees in the game.

## Prerequisites

1. Crusader Kings III 1.20.x, and a save from an older version (1.8 or later) that has running plots. Keep a backup of it.
2. Python 3.10 or newer.
3. **Never test on your only copy.** The tool never changes your save; it writes `<save>__updated__<version>.ck3` beside it. Back up your save folder anyway.

**Your save folder:**
- cmd.exe: `%USERPROFILE%\Documents\Paradox Interactive\Crusader Kings III\save games`
- PowerShell: `"$env:USERPROFILE\Documents\Paradox Interactive\Crusader Kings III\save games"`
- POSIX: `~/.local/share/Paradox Interactive/Crusader Kings III/save games` (Linux)

Run the commands below from that folder.

**Reset between sections:** delete the `__updated__` file the tool wrote, and nothing else.
- cmd.exe: `del "My Save__updated__*.ck3"`
- PowerShell: `Remove-Item "My Save__updated__*.ck3"`
- POSIX: `rm -f "My Save__updated__"*.ck3`

**While you play the updated save:** pause before you save (#42).

## High-Value Verification (~10 minutes)

### HV.1 -- The release installs and reports its version

- [ ] **Steps** (same in every shell):
  ```
  pip install --upgrade ck3-save-updater
  ck3update -V
  ```
- [ ] **Expected:** a version starting `0.4.24`.
- [ ] **Why this matters:** every check below assumes this build.

### HV.2 -- `status` names the old plots

- [ ] **Steps:** `ck3update status "My Save"`
- [ ] **Expected:** R29 reports "schemes in the old game's layout (frozen, with its old fields)", with a count. A save from 1.20 itself reports none.
- [ ] **Why this matters:** a player sees what will change before it happens.

### HV.3 -- The updated save's plots carry no old fields

- [ ] **Steps:** `ck3update update "My Save"`, then count the old fields in the new file. Replace `FILE` with the name the update printed (same command in every shell; the outer quotes are double, the inner single):
  ```
  python -c "from ck3_save_migrator import savefile as sf; g = sf.read_save('FILE').gamestate; print({k: g.count(k.encode()) for k in ('owner_influence=', 'scheme_freeze_days', 'status=continue', 'status=invalidated', 'last_update=1.1.1', 'freeze_data')})"
  ```
- [ ] **Expected:** `owner_influence=`, `scheme_freeze_days` and `freeze_data` are 0. `status=continue` plus `status=invalidated` equals `last_update=1.1.1`, which is the number of plots R29 reported. On the founding campaign: 1,314 + 20 = 1,334.
- [ ] **Why this matters:** an old field left in a plot is an error line in the game's log, once per plot.

### HV.4 -- The game logs no old plot field

- [ ] **Steps:** start the game with your playset, load the updated save, unpause and play a few months, then pause and quit. Open the game's `logs\error.log` (in the folder above `save games`).
  - cmd.exe: `findstr /c:"owner_influence" "%USERPROFILE%\Documents\Paradox Interactive\Crusader Kings III\logs\error.log"`
  - PowerShell: `Select-String -SimpleMatch "owner_influence" "$env:USERPROFILE\Documents\Paradox Interactive\Crusader Kings III\logs\error.log"`
  - POSIX: `grep -c owner_influence ~/.local/share/"Paradox Interactive/Crusader Kings III/logs/error.log"`
- [ ] **Expected:** no lines. Before 0.4.24 there was one "Unexpected token: owner_influence" per carried plot.
- [ ] **Why this matters:** this is the #7 error family this release removes.

### HV.5 -- Plots still run

- [ ] **Steps:** in the same game, open the Intrigue window of a character you know had a plot running in the old save.
- [ ] **Expected:** the plot is listed, its progress moves over the months you play, and a hostile plot shows its agent positions. Some plots conclude during the months you play.
- [ ] **Known limitation:** progress starts near the beginning of the plot's first phase, as the game itself does with an old plot. Older versions counted progress to 10, and the current game counts each phase to 70 to 730. Carrying progress across in proportion is planned.
- [ ] **Why this matters:** the conversion must not undo the thaw that 0.4.19 brought.

### HV.6 -- An old "+4 opinion with all vassals" artifact gives +4

- [ ] **Steps:** find an artifact that had "+4 opinion with all vassals" in the old game (in the founding campaign several do). Hover its modifiers in the artifact's window.
- [ ] **Expected:** two lines, +3 and +1 opinion with all vassals, adding up to +4, plus their small extras (a little prestige; scheme success and tax from happy powerful vassals). Before 0.4.24 it showed +5.
- [ ] **Why this matters:** the rule promises exact values where the current game can express them.

## Section 1: Edge cases

### 1.1 Running the update on an already updated save changes no plot

- [ ] **Steps:** `ck3update status "My Save__updated__1.20.x"` (the file from HV.3).
- [ ] **Expected:** R29 reports no schemes in the old layout.

### 1.2 Plots with no owner are marked invalidated

- [ ] **Steps:** in HV.3's output, read the `status=invalidated` count.
- [ ] **Expected:** the count of plots whose owner had died with no one taking over (20 on the founding campaign). The game marks exactly these plots invalidated when it loads an old save, and removes them.

### 1.3 An artifact with both an old +4 and an old +1

- [ ] **Steps:** if your save has one, hover its modifiers.
- [ ] **Expected:** +3 and two +1 lines, +5 in all. The game itself lists a bonus twice when an artifact rolled it twice.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| The conversion's exact text, the invalidated branch, the frozen form, slot placement, a second run | `tests/test_r29_scheme_thaw.py` | 9 |
| The +4 row (exact +3 and +1), +4 with +1 on one artifact | `tests/test_r25_successor_keys.py` | 2 of 23 |
| R25 to R30 counts on the founding save | `tests/test_rules.py::test_real_987_counts` (opt-in) | 1 |

The maintainers also compared the conversion with the game's own load-and-save output on all 1,334 plots of the founding campaign. 1,244 matched byte for byte. The other 90 differ only in the order the game lists a plot's script variables, which it stores keyed by name.

## What the automated tests DON'T cover

- How the plots look and behave in the Intrigue window, and whether they conclude.
- The artifact tooltip's wording and layout.
- Other old saves: the conversion was measured on one 1.8.1 campaign. A save from 1.9 to 1.19 may have plot fields this campaign lacked; R29 keeps an unknown field in its place.
- Mod plot types: a mod's plot is converted like any other, and keeps its fields.

## Reporting issues found

1. Note the section and step.
2. Capture the exact command and output, and the error.log lines.
3. Keep the `__updated__` file and the original.
4. Open an issue, or post in [GitHub Discussions](https://github.com/djdarcy/ck3-save-updater/discussions), naming this checklist and version 0.4.24.

## Cleanup

Delete the `__updated__` file (see Reset above). Restore your save folder from your backup if you changed anything else in it.
