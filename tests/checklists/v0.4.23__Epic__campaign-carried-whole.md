# Human Test Checklist: the campaign carried whole (0.4.9 to 0.4.23)

**Target version:** 0.4.23 (the v0.4.23 release)
**Ships with commit:** `67a6250` v0.4.23: R25 stacks kept tiers to rebuild a dropped artifact bonus exactly
**Companion automated tests:** 1,163 passed (6 skipped). The rules this checklist covers: `tests/test_r25_successor_keys.py` (22), `tests/test_r27_house_feuds.py` (4), `tests/test_r28_marriage_bed.py` (4), `tests/test_r29_scheme_thaw.py` (6), `tests/test_r30_asset_renames.py` (3). Plus the opt-in real-save test in `tests/test_rules.py` (`CK3_REAL_SAVES=1`).

## What this is

What a person runs to see the 0.4.x fidelity work for themselves: renamed units and artifacts, house feuds, childless marriages, running plots, artifact pictures, and the documentation of what does not carry over. The automated tests check the save's text. This checklist checks what a player sees in the game, which no test can.

## Prerequisites

1. Crusader Kings III 1.20.x, and a save from an older version (1.8 or later) that you keep a backup of. The founding campaign was a 1.8.1 save. Any old save with artifacts, plots and house feuds shows the most.
2. Python 3.10 or newer.
3. **Never test on your only copy.** The tool never changes your save; it writes `<save>__updated__<version>.ck3` beside it. Back up your save folder anyway.

**Your save folder:**
- cmd.exe: `%USERPROFILE%\Documents\Paradox Interactive\Crusader Kings III\save games`
- PowerShell: `"$env:USERPROFILE\Documents\Paradox Interactive\Crusader Kings III\save games"`
- POSIX: `~/.local/share/Paradox Interactive/Crusader Kings III/save games` (Linux)

**Reset between sections:** delete the `__updated__` file the tool wrote, and nothing else.
- cmd.exe: `del "My Save__updated__*.ck3"`
- PowerShell: `Remove-Item "My Save__updated__*.ck3"`
- POSIX: `rm -f "My Save__updated__"*.ck3`

**One rule while you play the updated save:** pause before you save (#42).

## High-Value Verification (~10 minutes)

### HV.1 -- The release installs and reports its version

- [ ] **Steps** (same in every shell):
  ```
  pip install --upgrade ck3-save-updater
  ck3update -V
  ```
- [ ] **Expected:** a version starting `0.4.23`.
- [ ] **Why this matters:** every check below assumes this build.

### HV.2 -- `status` shows the new steps before anything runs

- [ ] **Steps:** `ck3update status "My Save"` (your save's name)
- [ ] **Expected:** among the rules, R25 counts the keys it renames, and R27 to R30 report what they found. On an old save that has them:
  - house feuds by their two houses;
  - characters rejected from the marriage bed;
  - schemes frozen by the old game;
  - file references the game renamed.
- [ ] **Why this matters:** `status` is how a player sees what will change before it happens.

### HV.3 -- The update writes a new save and leaves yours alone

- [ ] **Steps:** `ck3update update "My Save"`
- [ ] **Expected:** a new `My Save__updated__1.20.x.ck3` beside your save. Your original's size and date are unchanged.
- [ ] **Why this matters:** the promise every release keeps.

### HV.4 -- Artifacts keep their pictures and models (R30)

- [ ] **Steps:** load the updated save in the game. Open your character's inventory and the court artifacts.
- [ ] **Expected:** unique artifacts (Excalibur, a relic, a crown) show their picture; armour artifacts show their model. None shows an empty frame.
- [ ] **Why this matters:** before 0.4.22 these showed blank, because 1.20 renamed the files.

### HV.5 -- An artifact bonus keeps its full value (R25 tier stacks)

- [ ] **Steps:** hover an artifact that had a strong building-cost bonus (the founding campaign's Stone of Scone had −7%).
- [ ] **Expected:** two building-cost lines that add up to the old value (−4% and −3%), not a single −4%.
- [ ] **Why this matters:** the solver rebuilds a strength the game dropped from smaller strengths of the same bonus.

### HV.6 -- Old plots run again, with agents (R29)

- [ ] **Steps:** open the schemes window of a character who had a plot in the old save. Unpause for a few game months, then pause.
- [ ] **Expected:** the plot is listed and its progress moves. A murder plot shows agent positions, some filled by the agents who had joined it.
- [ ] **Why this matters:** before 0.4.19 every carried plot was frozen for good.

## Section 1: Renamed things carry over (R25)

### 1.1 Units, innovations and looks

- [ ] **Steps:** in the updated save, open a ruler's army (Chu-ko-nu or holy-order units, if the old save had them) and a culture's innovations.
- [ ] **Expected:** Shenbigong or Order Serjeants in place of the old units; Gunpowder where Bombards was learned.

### 1.2 Vassal-opinion artifacts

- [ ] **Steps:** hover artifacts that gave opinion with all vassals.
- [ ] **Expected:** +1 stays +1, +3 is exactly +3 with a little prestige, +4 is +5, and +2 shows +5 and −3 as two lines.

### 1.3 County outcomes

- [ ] **Steps:** look at a county that had "Rice Fields" or a hold-court "Tax Relief".
- [ ] **Expected:** "Agricultural Innovation", or the current game's "Tax Relief", in their place.

## Section 2: Feuds and marriages (R27, R28)

### 2.1 A house feud is still a feud

- [ ] **Steps:** open the house view of a house that had a feud story in the old save, then its house relations.
- [ ] **Expected:** the rival house is listed at the feud level. After a year of play it is still a feud.

### 2.2 A childless marriage stays childless

- [ ] **Steps:** find a character who was "Rejected From Marriage Bed" in the old save (the relation is hidden, so check over time).
- [ ] **Expected:** no children with that spouse over several years of play, while other couples have them.

## Section 3: Saving and documentation

### 3.1 Pause before saving (#42)

- [ ] **Steps:** pause, then save from the menu.
- [ ] **Expected:** the save completes. (Saving while unpaused can crash an updated campaign; that is the known issue.)

### 3.2 What doesn't carry over

- [ ] **Steps:** read `docs/not-carried-over.md`, then compare with your save. For example: did a county have a "Weapons Ban in Cities"?
- [ ] **Expected:** each dropped item is listed by its in-game name, with what it did and when the game removed it. A link points to Discussions.

## What the automated tests DON'T cover

- How the game draws the result: pictures, models, tooltips, the schemes window.
- Whether a plot, a feud or a marriage behaves over years of play.
- How a stacked bonus reads in a tooltip.
- Saves from versions other than 1.8.1, and other mod sets.
- The save-while-running crash (#42), which depends on timing.

## Reporting issues found

1. Note the section and step.
2. Note your save's game version and mod list (`ck3update status` prints both).
3. Keep the `__updated__` save and your original.
4. File an issue at https://github.com/djdarcy/ck3-save-updater/issues, naming this checklist and version 0.4.23.

## Cleanup

Delete the `__updated__` saves you made (see "Reset between sections"). Your original saves were never changed.
