# Human Test Checklist: eminent holy sites for a carried custom faith, and the builder contracts

**Target version:** 0.5.22
**Ships with commit:** v0.5.22: a carried faith gets eminent holy sites; builder contracts (TBD hash)
**Companion automated tests:** 13 in `tests/test_builder_contracts.py`; 2 new in `tests/test_religion.py`; mutation report `tests/mutation/v0.5.22__sweep__builder-contracts.md`.

## What this is

A custom faith carried from an older save now gets one to three eminent holy sites, which 1.20 requires and 1.8 never had. Internally, every rule that builds an entry field by field now declares each field the game's own entries of that kind carry, and a test fails on any field it does not mention. The automated tests prove the declarations and the derivation; this checklist is the in-game look and the one check a person should make of the contract test itself.

## Prerequisites

1. ck3-save-updater 0.5.22, and an old save with a custom faith (one you founded or reformed in 1.8 or earlier).
2. Update it to a test copy named with the `MIGRATE_TEST__` prefix, so your own saves are untouched.
3. The in-game step is yours to run; nothing here launches the game.

---

## High-Value Verification (~10 minutes, most of it the game loading)

### HV.1 -- The faith screen shows eminent holy sites

- [ ] **Steps:** load the `MIGRATE_TEST__` save; open your custom faith's screen, Holy Sites.
- [ ] **Expected:** one to three sites are marked eminent, and each is one of the faith's own holy sites.
- [ ] **Why this matters:** 1.20 requires at least one; a faith with none is a state the game never makes itself.

### HV.2 -- The god's name still shows

- [ ] **Steps:** on the same faith screen, read the name of the god (or wait for an event that names it).
- [ ] **Expected:** "God" for a faith made from a Christian one, never a blank (the 0.5.18 fix stays fixed).

### HV.3 -- Lint no longer names either field

- [ ] **Steps:** `python -m ck3_save_migrator lint "<the MIGRATE_TEST__ save>"`
- [ ] **Expected:** no line naming `eminent_holy_sites` or `faith_type`. Other field lines (artifacts, cultures, titles...) are the gaps still open.

### HV.4 -- The contract test catches a field it does not know

- [ ] **Steps:** in a checkout, copy `ck3_save_migrator/baselines/1.20.1.2/fields.json` aside; add `"a_new_field": [1.0, 0.0],` inside `faiths/database`'s `fields`; run `python -m pytest tests/test_builder_contracts.py -q`; then restore the copy.
- [ ] **Expected:** the test for `faiths/database` fails and names `a_new_field`; after the restore it passes.
- [ ] **Why this matters:** this is what makes a new game version's new field fail in the tests, not in a player's game.

  Restore (pick your shell): **cmd.exe** `copy /Y fields.json.bak ck3_save_migrator\baselines\1.20.1.2\fields.json` -- **PowerShell** `Copy-Item fields.json.bak ck3_save_migrator\baselines\1.20.1.2\fields.json -Force` -- **POSIX** `cp fields.json.bak ck3_save_migrator/baselines/1.20.1.2/fields.json`

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| every field of the game's faiths, rites, organizations, contracts and opinions is declared; reasons and statuses; lint's allow-list is the declarations | `tests/test_builder_contracts.py` | 9 |
| the eminent-site derivation (origin's eminent among its own, fallback, cap of 3, none without holy sites); faith_type of an empty or missing type | `tests/test_builder_contracts.py` | 3 |
| the contract entry writes exactly its declared fields | `tests/test_builder_contracts.py` | 1 |
| R10's faith on the fixture: 1-3 eminent sites among its own; only declared fields written | `tests/test_religion.py` | 2 |

## What the automated tests DON'T cover

- How the game shows eminent sites, and whether it accepts the derived choice.
- Faiths whose origin faith has no eminent sites at all (the fallback to the first holy site), in the game.
- Mods that add their own faith fields.

## Reporting issues found

Note the step, the save's faith and its holy sites, the lines printed, and keep the `MIGRATE_TEST__` copy.

## Cleanup

Delete the `MIGRATE_TEST__` save and `fields.json.bak` when done (recoverable deletes preferred).
