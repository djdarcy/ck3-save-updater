# Human Test Checklist: the three faith edits

**Target version:** 0.5.28 (the edits shipped in 0.5.25, 0.5.26 and 0.5.27; 0.5.28 adds their documentation)
**Ships with commit:** v0.5.28 (docs and this checklist)
**Companion automated tests:** 41 tests: `tests/test_edit_eminent.py` (10), `tests/test_edit_set_faith.py` (10), `tests/test_edit_doctrines.py` (14), `tests/test_faith_lookup.py` (7)

## What this is

Three edits change faith in a 1.20 save: `set-eminent-holy-sites`, `set-faith` and `set-doctrines`. The automated tests run them on small synthetic saves and a fake game folder. This checklist runs them on a real save and a real game install, reads what they print, and loads the results in the game. Anyone with Crusader Kings III 1.20 and a text save can run it.

## Prerequisites

1. Crusader Kings III 1.20 installed through Steam, or its `game` folder at a known path.
2. `ck3update` 0.5.28 or later (`ck3update --version`), or `python -m ck3_save_migrator` from a checkout.
3. A **copy** of a 1.20 text save (not ironman) in a scratch folder. Never run these steps on a save you play. Below it is called `Test.ck3`.
4. You need the ids or names of a faith and a character in that save. `ck3update edit Test.ck3 artifacts <a character>` prints a character's id line, and a faith can be named by its name as the game shows it.

Make the scratch folder and the copy (pick your shell):

**cmd.exe**:
```cmd
mkdir %TEMP%\faith-test
copy "<your save>.ck3" %TEMP%\faith-test\Test.ck3
cd /d %TEMP%\faith-test
```

**PowerShell**:
```powershell
New-Item -ItemType Directory -Force "$env:TEMP\faith-test" | Out-Null
Copy-Item "<your save>.ck3" "$env:TEMP\faith-test\Test.ck3"
Set-Location "$env:TEMP\faith-test"
```

**POSIX**:
```bash
mkdir -p /tmp/faith-test
cp "<your save>.ck3" /tmp/faith-test/Test.ck3
cd /tmp/faith-test
```

**Reset between sections:** delete the `Test__*.ck3` and `Test__*.edits.json` files the edits wrote (`del Test__*` in cmd.exe, `Remove-Item Test__*` in PowerShell, `rm -f Test__*` in POSIX). `Test.ck3` itself is never changed by any step.

## High-Value Verification (~5 minutes)

If you only have 5 minutes, run these. If one fails, the edits are broken.

### HV.1 Eminent holy sites, one line changed

Validates: `set-eminent-holy-sites` writes the faith's eminent list and nothing else.

- [ ] **Steps:** `ck3update edit Test.ck3 set-eminent-holy-sites "<faith>" "<one to three of its holy sites>" --dry-run`
- [ ] **Expected:** a `target` line naming the faith's old and new eminent sites, and exactly one `change at` line, from `eminent_holy_sites={ ... }` to the new list.
- [ ] **Why this matters:** an edit that touches more than the one line could change a faith the player did not mean to change.

### HV.2 A site the faith does not hold is refused

- [ ] **Steps:** the same command with a holy site that is not one of the faith's own.
- [ ] **Expected:** `ERROR: set-eminent-holy-sites: <site> (<n>) is not among the faith's holy sites (...)`, with the game file `50_holy_site_decisions.txt` cited. No file is written.
- [ ] **Why this matters:** the game itself refuses this; writing it would make a save the game never makes.

### HV.3 A character's rite, by spelling or by faith

- [ ] **Steps:** `ck3update edit Test.ck3 set-faith <character id> "Shafi'i" --dry-run`, then `... set-faith <character id> sunni --dry-run`
- [ ] **Expected:** the first changes `rite=` to Shafi'i's number. The second gives Sunni's main rite, and the target line says "the main rite of Sunni". When the faith changes, the line warns about same-faith succession.
- [ ] **Why this matters:** players type names, not numbers. A faith meaning its main rite is the conversion a player expects.

### HV.4 A doctrine fills an empty group or replaces the current one

- [ ] **Steps:** `ck3update edit Test.ck3 set-doctrines "<faith>" "+doctrine_pilgrimage_encouraged" --dry-run`
- [ ] **Expected:** the target line reads `doctrine_pilgrimage: <current or empty> -> doctrine_pilgrimage_encouraged`. There are two changes, one in the faith and one in its main rite, unless the faith already has it.
- [ ] **Why this matters:** the faith and its rite must say the same thing, or the game reads one and the player sees the other.

### HV.5 What the game forbids is refused with its rule, and `--dangerous` forces it

- [ ] **Steps:** on a Christian faith with three tenets, `ck3update edit Test.ck3 set-doctrines "<faith>" "-<one tenet> +tenet_christian_syncretism" --dry-run`. Then the same with `--dangerous`.
- [ ] **Expected:** the first is refused with `tenet_christian_syncretism cannot be chosen by a faith of christianity_religion (00_tenet_types.txt:...)`. The second shows the changes and ends with `forced: ...`.
- [ ] **Why this matters:** refusals must cite the game's rule so a player can check it. `--dangerous` must still let the player do it on purpose.

## Section 1: set-eminent-holy-sites

### 1.1 Real run and the ledger
- [ ] Run HV.1 without `--dry-run`, answering `y`.
- [ ] **Expected:** `Test__set-eminent-holy-sites.ck3` and its `.edits.json` appear. `Test.ck3` is unchanged (same size and date).

### 1.2 Counts and duplicates
- [ ] Run it with no sites (`""`), with four sites, and with the same site twice.
- [ ] **Expected:** each is refused, saying "1 to 3 eminent holy sites, not N" or "a site is named twice". Nothing is written.

### 1.3 Already set
- [ ] Run it with the sites the faith already has.
- [ ] **Expected:** an error saying the eminent holy sites are already those. Nothing is written.

## Section 2: set-faith

### 2.1 By name
- [ ] Run `set-faith "<first name>" <rite>` with a first name several characters share.
- [ ] **Expected:** a refusal listing the candidates with ids, as other edits do.

### 2.2 Unknown target
- [ ] Run `set-faith <id> shafi` (misspelled).
- [ ] **Expected:** `'shafi' is neither a rite nor a faith (no rite 'shafi'; nearest: shafii; ...)`.

### 2.3 A dead character
- [ ] Run `set-faith <a dead character's id> <rite>`, then the same with `--dangerous --dry-run`.
- [ ] **Expected:** the first is refused as dead. The second shows the change and `dead: forced`.

### 2.4 A custom faith's rite reads by its faith
- [ ] For a character of a custom (player-made) faith, run any `set-faith` dry run.
- [ ] **Expected:** the old rite reads as `<faith name>'s own rite (<n>)`, not `?`.

## Section 3: set-doctrines

### 3.1 A tenet swap
- [ ] `set-doctrines "<faith>" "-<tenet it has> +<a tenet it lacks>" --dry-run`
- [ ] **Expected:** `tenet <old> -> <new>`, written in place in the faith and its main rite.

### 3.2 Each refusal
Run each with `--dry-run` and check the cited rule:
- [ ] `+<a fourth tenet>`: "a faith holds 3 tenets, not 4 (00_defines.txt:...)".
- [ ] On a faith that already holds a syncretism tenet, `+<a second syncretism tenet>`: both the cap message and "a faith may hold only one of ... (unique_syncretism_trigger, 00_religious_triggers.txt:...)".
- [ ] On a Christian faith, `-special_doctrine_is_christian_faith`: "is carried by every faith of christianity_religion and is not a faith's to drop (00_christianity.txt:...)".
- [ ] `-<its funeral doctrine>`: "leaves doctrine_funeral (clergy) with no doctrine".
- [ ] `+doctrine_made_up`: "is not a doctrine or tenet the game defines".

### 3.3 Without the game folder
- [ ] Hide the game from the tool and run any `set-doctrines` (pick your shell):
  - **cmd.exe**: `set CK3_GAME_DIR=%TEMP%\no-such-game` (if the tool still finds Steam, run this on a machine without the game, or skip)
  - **PowerShell**: `$env:CK3_GAME_DIR = "$env:TEMP\no-such-game"`
  - **POSIX**: `export CK3_GAME_DIR=/tmp/no-such-game`
- [ ] **Expected:** if the tool cannot find the game, it refuses with "the game's own files are needed ... set CK3_GAME_DIR". It never writes without the rules, even with `--dangerous`.
- [ ] Unset afterwards: `set CK3_GAME_DIR=` / `Remove-Item Env:\CK3_GAME_DIR` / `unset CK3_GAME_DIR`.

## Section 4: Revert

- [ ] After any real run, `ck3update edit Test__set-doctrines.ck3 revert --yes` (or the file the run wrote).
- [ ] **Expected:** a new file, `Test__set-doctrines__revert.ck3`, whose game state matches `Test.ck3` (checked on a 1.20 save on 2026-11-16: identical). Its `.edits.json` records the revert.

## Section 5: In the game (MANUAL)

These need a person and the game. Load each save from the main menu, then check the screen named.

- [ ] **Eminent holy sites:** the faith's screen shows the chosen sites as eminent. The others are still holy sites.
- [ ] **set-faith:** the character's faith shows the new rite. (Maintainer's founding campaign: confirmed on 2026-11-16, Gabrán shows as Shafi'i.)
- [ ] **Pilgrimage:** the faith's doctrines show the pilgrimage doctrine chosen. Pilgrimage is open to its characters.
- [ ] **Forced Christian Syncretism:** note what the game does with a Christian faith holding Christian Syncretism without Teachings of Jesus. That includes whether it loads, what the faith screen shows, and whether the game puts anything back on load. This is a finding to record, not a pass or fail.

The maintainer's staged saves for the founding campaign are named `MIGRATE_TEST__v16__set-eminent-holy-sites`, `__set-faith`, `__pilgrimage` and `__forced-syncretism`.

|---|---|---|

## What the automated tests DON'T cover

- The real game install's files. The tests use a small fake game folder. A game update that renames a doctrine, moves a rule or changes a trigger is caught only by a run against the real game.
- Whether the game accepts the result. Only loading the save shows that, especially for the forced change.
- Reading the output. Are the target lines clear, and do the refusals say enough to act on?
- Finding the game through Steam on a machine set up differently from the developer's.
- Long faith names and non-ASCII names in a Windows console.

## Reporting issues found

1. Note the section and step.
2. Copy the exact command and its output.
3. Keep `Test.ck3` and the output it wrote.
4. File an issue naming this checklist and the version from `ck3update --version`.

## Cleanup

Delete the scratch folder: `rmdir /s /q %TEMP%\faith-test` (cmd.exe), `Remove-Item -Recurse "$env:TEMP\faith-test"` (PowerShell), `rm -rf /tmp/faith-test` (POSIX). Unset `CK3_GAME_DIR` if you set it in Section 3.3.
