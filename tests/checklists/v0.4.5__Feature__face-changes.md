# Human Test Checklist: `--face-changes` and the wrong-layout warning

**Target version:** 0.4.3 to 0.4.5
**Ships with commit:** v0.4.5 (`5e6fabb`), with v0.4.4 (`dce80b9`) and v0.4.3 (`f6cd681`)
**Companion automated tests:** 28 tests in `tests/test_dna_renames.py` (6), `tests/test_dna_merges.py` (4), `tests/test_dna_fallback.py` (6), and `tests/test_dna_old_mods.py` (12, 1 of them new for the warning's share)

## What this is

The face changes are opt-in switches that change bytes in a save's faces. The tests prove the bytes, and an end-to-end run on one real campaign proved the default output unchanged. Neither shows whether a face *looks* closer to how it was. That takes a person with the game open. This checklist is for a maintainer, or a player with a pre-1.20 save and its old portrait mods.

## Prerequisites

1. `ck3update` 0.4.5 or later (`pip install ck3-save-updater`, or `python -m ck3_save_migrator` from a checkout).
2. A pre-1.20 save that used portrait mods (Ethnicities & Portraits Expanded, Community Flavor Pack), and the mods' builds from that time (`--old-portrait-mods`).
3. **Work on a copy of the save.** `update` never changes the save it is given (it writes `<name>__updated__<version>.ck3` beside it), but keep a copy anyway.
4. For the screenshot section: the game, and a backup of your game Documents folder (settings and `dlc_load.json`). Name every save you stage `MIGRATE_TEST__...` so you can find and remove them later.

## High-Value Verification (~10 minutes, no game)

### HV.1 -- the default is unchanged

Validates: no switch is on unless asked.

- [ ] **Steps** (same in every shell):
  ```
  ck3update update "<save>" --old-portrait-mods <cfp>,<epe>
  ck3update update "<save>" --old-portrait-mods <cfp>,<epe> --face-changes none
  ```
- [ ] **Expected:** the two outputs are byte-identical (compare with any file hash: `certutil -hashfile <file> SHA256` in cmd, `Get-FileHash <file>` in PowerShell, `sha256sum <file>` in POSIX). Rename the first output before the second run, since both write the same name.
- [ ] **Why this matters:** a player who never asked for a face change must get 0.4.0's faces.

### HV.2 -- each switch is accepted, and an unknown one is refused

- [ ] **Steps:**
  ```
  ck3update status "<save>" --face-changes renames,merges,fallback
  ck3update status "<save>" --face-changes colours
  ```
- [ ] **Expected:** the first runs. The second stops with `--face-changes "colours" is not a known change; known: none, renames, merges, fallback`.
- [ ] **Why this matters:** a typo must not silently fall back to the default.

### HV.3 -- the report names what each switch did

- [ ] **Steps:** run `update` with `--face-changes renames,merges,fallback`, then open `<output>.report.json`.
- [ ] **Expected:** R19's `plans` list `renamed`, `merged` and `fell_back` for your save's layouts. Any gene in `renamed` or `merged` is not also in `dropped`.
- [ ] **Why this matters:** a player can see which old genes came across and how.

### HV.4 -- the wrong-layout warning

- [ ] **Steps:**
  ```
  ck3update status "<save>"
  ck3update status "<save>" --old-portrait-mods <cfp>,<epe>
  ```
- [ ] **Expected:** without the old builds (when today's mods differ from the save's), the NOTES say "the source layout is probably not the save's". With the right builds that line is gone. A handful of undefined template indexes, if any, read "too few to doubt the source layout (N of M template bytes)".
- [ ] **Why this matters:** the warning is how a player learns to give `--old-portrait-mods`; a false alarm teaches them to ignore it.

## Section 1: the joint look (screenshots, ~30 minutes, needs the game)

Done together by the maintainers, on the same characters every time: two the founding campaign's players know, and two whose faces use the late-2022 eye genes. For each character there are two looks: `--face-changes none`, and `renames,merges,fallback` with the stand-in for the late-2022 genes added to `--old-portrait-mods`.

### 1.1 Stage each look

- [ ] **Steps** (from a checkout; every command is the same in every shell):
  1. Back up the Documents folder: `python -I tests/one-offs/docs_guard.py snapshot <box>`.
  2. For each character and look, put the character's face on the player's portrait at age 30. This writes a `MIGRATE_TEST__` save:
     `python -I tests/one-offs/dna_show_as_player.py <look output.ck3> <look output.ck3> <character id> 30 "<save games>/MIGRATE_TEST__f40_r1_<name>_<look>.ck3" --keep-layout`
  3. Load each one with the playset you play with and take the screenshot:
     `bash tests/one-offs/play7_shots.sh f40-r1-<name>-<look> MIGRATE_TEST__f40_r1_<name>_<look>.ck3 60`
     (POSIX shell; on Windows, Git Bash. It backs up and restores `dlc_load.json` byte for byte.)
  4. Build the sheet: `python -I tests/one-offs/face_round.py r1 <name> none=<run dir> all=<run dir>`.
- [ ] **Expected:** one sheet per character, the two looks side by side.
- [ ] **Check:** `python -I tests/one-offs/docs_guard.py check <box>` prints `0 differences`.

### 1.2 Judge

- [ ] For each sheet: does the right face look closer to the character as you remember them? Write one line per character.
- [ ] A switch becomes a default only on this verdict, and only then does the campaign's golden output get a new hash.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| renames: carried by name, never when the source has the new name, never when the target lacks it, opt-in, option parsing | `tests/test_dna_renames.py` | 6 |
| merges: lands on the new template at the same weight, never overwrites a set weight, opt-in, off means dropped | `tests/test_dna_merges.py` | 4 |
| fallback: closest name, never a template that draws nothing, index 0 kept where it draws, opt-in | `tests/test_dna_fallback.py` | 6 |
| the warning's share: a handful among 1,000 faces is not called the wrong layout | `tests/test_dna_old_mods.py` | 1 new (12 in the file) |

## What the automated tests DON'T cover

- Whether a face looks closer to the original: only the game can draw it.
- A real save's size and mod set: the tests use synthetic layouts of a few genes.
- The game's own handling of a template it no longer defines, or of a negative blendshape weight.
- The wording of the NOTES lines at a real terminal width.

## Cleanup

- Remove every staged save by name (`MIGRATE_TEST__f40_r1_*`): `del` in cmd, `Remove-Item` in PowerShell, `rm` in POSIX (or `dz safedel` where available).
- `python -I tests/one-offs/docs_guard.py check <box>` again: `0 differences`.
- If `dlc_load.json` differs, `docs_guard.py restore <box>` puts it back.

## Reporting issues found

Note the section and step, the exact command and output, and the save's game version and mods. File an issue that references this checklist and #40.
