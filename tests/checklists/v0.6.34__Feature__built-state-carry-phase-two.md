# Human Test Checklist: the built-state carry, phase two (holding tiers and regular districts)

**Target version:** 0.6.34
**Ships with commit:** v0.6.34 (the built-state carry, phase two)
**Companion automated tests:** 25 new tests:
- `tests/test_host_rules.py` (3 new: district enable conditions, tier and trade-good gates, slot formulas);
- `tests/test_district_lint.py` (2, real saves only: the fresh 1.21 game nearly clean, a known-bad save flagged);
- `tests/test_holding_tiers.py` (3: raised to the witness's tier, never lowered, refused when undefined);
- `tests/test_carry_districts.py` (6: tiers kept in a raised district, the cap policy, disabled districts and missing goods, open families named, prerequisites, existing districts untouched);
- `tests/test_successor_table.py` (3: every family carried or explained, locked rows open, successors hosted);
- `tests/test_update.py` (the phase-two plan names R44 and R42 as needing `--witness`).

## What this is

When Crusader Kings III converts a 1.20 save to 1.21, it keeps each holding's main building at tier 1 and leaves every other building out: the new regular districts come out empty. Two new repairs in `update --witness` bring some of that back:
- **R44** puts each holding's main building back at the tier the last 1.20 save had.
- **R42** writes the last 1.20 save's regular buildings into the empty districts, where the game's own rules allow them.

Every building it can't place is named in the report, with the reason. This checklist is for whoever confirms that in the game: the districts appear, the game keeps them, and nothing illegal is written.

## Prerequisites

1. Crusader Kings III 1.21 installed; the tool installed (`pip install -e .` from the repo, or the release).
2. Three saves:
   - **A**: your campaign's **last 1.20 save** (the witness);
   - **B**: the same save **loaded once in 1.21 and saved immediately**, without playing on;
   - **R**: a 1.21 reference (a fresh 1.21 game saved on the same start date, or the one `reference-mod` sets up).
3. **Work on copies.** Name every file you add to the save folder with the prefix `MIGRATE_TEST__`, so it can't be mistaken for a real save.
4. **When saving from the in-game console, avoid dots in the name.** The game cuts the name at the first dot: `save MIGRATE_TEST__1.21-x` writes `MIGRATE_TEST__1.ck3`.
5. **Reset between sections:** delete the `MIGRATE_TEST__` outputs you made, and keep A, B and R.

## High-Value Verification (~10 minutes plus one game load)

### HV.1: the update runs R44 and R42 and names what it left out

Validates: both repairs run on the real route, and the report accounts for every building.

- [ ] **Steps** (same in every shell; `ck3update` is the tool's own command):
  ```
  ck3update update "B.ck3" --witness "A.ck3" --reference "R.ck3" -o "MIGRATE_TEST__carry.ck3"
  ```
- [ ] **Expected:**
  - The plan lists `R44 holding-tiers-from-witness runs` and `R42 districts-from-witness runs`.
  - The summary shows R44 with a "restored" count, and R42 with district and building counts.
  - The report (`MIGRATE_TEST__carry.report.json`) lists, under R42, `open` (families with no successor yet, e.g. guild halls), `refused` (not legal there, e.g. pastures in a county with no livestock good) and `dropped` (e.g. "manor_houses_district needs villages_district").
- [ ] **Why this matters:** without the repairs a converted realm has no regular buildings; without the report a player can't tell what was lost.

### HV.2: a carried holding shows its districts in the game

- [ ] **Steps:** load `MIGRATE_TEST__carry.ck3` in 1.21. Open a county capital you remember having farms or pastures in (the founding campaign's test case is Rome), then its holding view.
- [ ] **Expected:**
  - A villages district whose level matches its buildings: Rome shows level 3, with farming fields 3 and meadowlands pastures 2.
  - The holding's main building at its old tier: Rome's castle at tier 2.
- [ ] **Why this matters:** this is the player-visible result of the whole carry.

### HV.3: the game keeps what was written

- [ ] **Steps:** in the console, `save MIGRATE_TEST__carry_resaved` (no dots). Then compare district counts before and after, with the lint (any shell):
  ```
  python -c "from ck3_save_migrator import host_rules as H, district_lint as L; from ck3_save_migrator.savefile import read_save; G=r'<game>/game'; g=read_save(r'MIGRATE_TEST__carry_resaved.ck3').gamestate; r=L.lint(g,H.load(G),L.province_facts(g,G)); print(r.districts, r.buildings, dict(r.by_kind()))"
  ```
- [ ] **Expected:** the same district and building counts as the output (founding campaign: 1,764 districts, 1,985 buildings), and no breaches.
- [ ] **Why this matters:** the game keeps illegal district states silently, so "it loaded" proves nothing. The lint is what shows the carried state is legal.

### HV.4: a holding that isn't its county's capital gets no walls district

- [ ] **Steps:** in the game, open a barony that had curtain walls or ramparts in 1.20 and is not its county's capital.
- [ ] **Expected:** no walls district (1.21 enables walls only in a county capital), and the building listed under `refused` in the report.
- [ ] **Why this matters:** a walls district there would be inert, a state no 1.21 game makes.

### HV.5: a save played on since the conversion is left alone

- [ ] **Steps:** play B on a few days in 1.21 and save it (`MIGRATE_TEST__played`). Then:
  ```
  ck3update update "MIGRATE_TEST__played.ck3" --witness "A.ck3" --reference "R.ck3" -o "MIGRATE_TEST__played_out.ck3"
  ```
- [ ] **Expected:** R44 and R42 report "skipped", saying the witness is dated earlier than the save and that repairs would overwrite play.
- [ ] **Why this matters:** a restore must never undo what the player did after converting.

## What the automated tests DON'T cover

- **How a carried holding looks in the game's holding view:** levels, icons, empty slots.
- **Whether carried buildings pay out after play.** Income and levies need the game's monthly tick, so play a few months and compare a carried holding with a similar uncarried one.
- **1.21's "Situation" windows pause the game until clicked.** An unattended run sits on day one; someone has to click their button.
- **Gated tribal districts:** every tribal regular district in 1.21 depends on a trigger, so no tribal building is carried yet. Confirm tribal holdings report their buildings under `open` or `refused`.
- **Other campaigns, mods and start dates.**

## Reporting issues found

1. Note the section and step.
2. Keep the `MIGRATE_TEST__` output and its `.report.json`.
3. File an issue naming this checklist and version 0.6.34.

## Cleanup

Delete the `MIGRATE_TEST__` files you made in the save folder: the outputs, their `.report.json` and `.lint.json`, and the re-saves. A, B and R stay.
